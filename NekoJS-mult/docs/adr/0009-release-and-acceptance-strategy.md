# 迁移发布与验收策略

架构重设计的全部模型决策（ADR-0001~0008）已锁定，本 ADR 定**落地与验收**策略：

1. **三阶段两发布**：P1（扩展点系统）可独立发布验证——插件 API breaking、脚本用户无感；P2（通用注册表 + 脚本面切换）是**唯一面向脚本的 breaking 发布**（大版本号，配 validator 迁移提示与 wiki 迁移表，ADR-0006）；P3（模块与守卫治理）无破坏收尾。breaking 只发生一次。
2. **14 个内置 EP 迁移直接 breaking**（不留 deprecated 适配期，与 R3"一次性切换"哲学一致）；`NekoPluginRuntime` 访问器迁移期保留委托、**P1 末删除**。
3. **判据验收**：①新增注册表类型 ≤ 1 类、②新增扩展点 = 1 文件 + 清单 1 行——**试做验收**（P2 末真做一次，数变更文件数）；③贡献者零文档上手——**真人测试**（理想人选 ZZZank，痛点文档作者）。
4. **`guardLint` + `common-api-processor` 挂 CI 强制**（gradle 任务现成，边际成本近零）。
5. **Fabric adapter** 于 P2 后启动、与 P3 并行（registry adapter 就绪即接 LoaderBridge）；Forge 1.20.1 端口照项目原 roadmap（B4 之后），不在本图范围。

## Consequences

- P1/P3 各是一次可回滚的小发布；P2 是承诺过的一次性阵痛（大版本）。
- CI 强制后，守卫密度与模块边界违规在合入前拦截。

## 修订（2026-08-30）

第 5 条关于 Forge 1.20.1 端口的部分已作废：Forge 1.20.1 支持取消，骨架自仓库移除。它的 API 与版本树差了一个时代，守卫和 replacements 桥接不了，移植等于维护第二套代码库。Fabric 部分不变。
