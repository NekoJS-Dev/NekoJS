## 目标与范围

在同一引擎配置模型中独立选择实际前端、源码检查列表和产物检查列表，并校验输入阶段与语义兼容。历史设计中的 languagePipelines、frontend、sourceChecks、outputChecks 仍是待审格式，不是已支持配置键。

- 统一不可变的扩展名到流水线描述映射；复用 D1 的候选身份和原子捕获、D2 的检查提供者，不建立并行注册表或第二个运行时所有者。
- 配置缺省与显式空数组必须区分。缺省保留 #69 修复后的默认策略；显式空数组关闭该阶段，不能悄悄回退。现有 scriptMemberValidation=false 关闭所有预检查，但不关闭编译语法校验、授权或沙箱。
- 冻结注册完成后、允许脚本运行前解析整个组合。验证阶段、源码／产物表示、方言、能力与语义；相同语言字符串或厂商不能证明兼容，未知能力也不能默认兼容。
- 源码检查在准备前、产物检查在准备成功后执行；单阶段按数组顺序，拒绝重复检查 ID；不得因安装某插件就隐式执行所有检查器。
- 错误配置、缺失提供者和不兼容组合必须定位明确且不静默替换；普通诊断与检查器失败、编译失败分开处理。缓存键隔离提供者、修订、阶段和输入事实，schema/接收端不跨代际复用。
- 入口、依赖、CJS/ESM 和各 Script Type 使用同一策略。普通 reload 保持启动策略，变更需要重启。保持授权、source map、文件与状态合同。
