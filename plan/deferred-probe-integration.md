# D4：Probe 选择与流水线集成

状态：延期；仅本地任务票，未实施，未创建 GitHub issue。前置：[D3 可组合流水线](deferred-composable-pipeline.md)。

## 目标与范围

让流水线能够引用已有 Probe 后端，并在复用既有注册表与文件事务的前提下统一有效选择。保留现有 (languageId, name) 身份，不新建 Probe 注册协议；兼容元数据如需扩展，采用可选描述／适配方式，不默认认可第三方未知能力。

- 将 Probe 的目标语义与前端／检查器的实际能力关联，不能机械要求语言字符串一致；JS 配 TypeScript 声明可能合法，Python 原文配 JS-only 源码检查不合法。
- 待审选择优先级：显式命令参数 > 引擎流水线对目标语言的引用 > 现有 Probe 语言级配置 > 注册表默认。命令覆盖只影响当次生成，不切换运行时前端或预检查。
- 显式流水线引用缺失或不兼容时不静默回退。旧 Probe 配置回退语义应单独核对，不能把新增 fail-closed 语义扩散到所有旧配置。
- 多扩展名指向同一 Probe 目标语言却选择不同后端时，初始化即报告冲突，避免共用输出目录互相覆盖。
- 无参数命令保持既有 TypeScript 默认目标；all、启动生成和编辑器协调器共用有效选择结果。任何目标选择集合或默认行为变更都须明确说明并测试。
- 既有扫描、输出目录、提交、回滚和清理仍由 Probe 模块拥有；引擎配置只引用后端，不复制整个 Probe 配置，不绕过权限与安全限制。
