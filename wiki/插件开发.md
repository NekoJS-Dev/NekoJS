# 插件开发

> 本页教你写一个 **NekoJS 插件 mod**（addon）—— 即一个独立的 mod，给 NekoJS 添加新的绑定、事件、适配器、配方 schema 等。

## 插件是什么

NekoJS 的扩展模型是**插件即 API**：内置功能（`NekoJSCorePlugin`）和第三方插件实现同一个接口 `NekoJSPlugin`，走同一套钩子。

一个插件就是：
1. 一个实现 `NekoJSPlugin` 的类。
2. 标 `@RegisterNekoJSPlugin` 注解。
3. 实现 你需要的钩子（default 方法全是空实现，按需覆盖）。

NekoJS 会在 bootstrap 时自动发现、实例化、排序你的插件类，并调用它的钩子。

## 最小插件

```java
package com.example.myaddon;

import com.tkisor.nekojs.api.NekoJSPlugin;
import com.tkisor.nekojs.api.annotation.RegisterNekoJSPlugin;
import com.tkisor.nekojs.api.data.BindingRegistry;

@RegisterNekoJSPlugin(
    priority = 500,
    requiredMods = { "mymod" }    // 仅当 mymod 加载时启用本插件
)
public class MyAddonPlugin implements NekoJSPlugin {

    @Override
    public void registerBinding(BindingRegistry registry) {
        registry.register("MyHelper", new MyHelperJS());
    }
}
```

```java
package com.example.myaddon;

import com.tkisor.nekojs.api.Doc;            // 见注解体系页
import com.tkisor.nekojs.api.annotation.Doc;

public class MyHelperJS {
    @Doc("把两个数字加起来")
    public int add(int a, int b) { return a + b; }
}
```

这样脚本里就能用 `MyHelper.add(1, 2)` → `3`。

## @RegisterNekoJSPlugin 详解

```java
@RegisterNekoJSPlugin(
    priority = 1000,                  // 加载优先级，数字越大越先（默认 1000；内置 CORE_PRIORITY = Integer.MAX_VALUE）
    clientOnly = false,               // 仅客户端加载
    requiredMods = { "mymod" },       // 仅当所有列出的 mod 都存在时加载（AND）
    provides = {                      // 声明性 descriptor（见下）
        @ProvidesBinding(name = "MyHelper", scriptTypes = { ScriptType.SERVER, ScriptType.STARTUP })
    },
    requiresNekojs = "[1.1.0,2.0)"    // 要求的 NekoJS 版本范围
)
```

| 元素 | 默认 | 作用 |
|---|---|---|
| `priority` | `1000` | 加载优先级（降序）。`CORE_PRIORITY` 保证内置插件最先。 |
| `clientOnly` | `false` | 仅客户端进程加载（专用服务器跳过）。 |
| `requiredMods` | `{}` | 所有列出的 mod 都存在才加载。 |
| `provides` | `{}` | 声明提供的 bindings/events/adapters（descriptor，用于冲突检测）。 |
| `requiresNekojs` | `""` | 要求的 NekoJS 版本范围。 |

## NekoJSPlugin 钩子一览

所有方法都有 default 空实现，按需覆盖：

### 生命周期

| 钩子 | 时机 |
|---|---|
| `init()` | 插件初始化 |
| `initStartup()` | 启动阶段初始化 |
| `afterInit()` | 所有插件 init 后 |
| `beforeScriptsLoaded(ScriptType)` | 每种脚本加载前 |
| `afterScriptsLoaded(ScriptType)` | 每种脚本加载后 |
| `beforeRecipeLoading(...)` | 配方加载前（可改原始 JSON map） |
| `afterRecipes(...)` | 配方脚本跑完 |

### 绑定与类型

| 钩子 | 作用 |
|---|---|
| `registerBinding(BindingRegistry)` | 注册全局 JS 绑定（详见下） |
| `registerAdapters(JSTypeAdapterRegistry)` | 注册 JS→Java 类型适配器（见 [类型适配器](类型适配器)） |
| `registerTypeDocs(TypeDocsRegister)` | 注册类型文档（与 `@Doc` 注解等价的编程式 API） |
| `registerNodeTypeDocs(...)` | 注册 Node 模块类型声明 |
| `registerNodeModules(...)` | 注册 Node 兼容模块 |

### 事件

| 钩子 | 作用 |
|---|---|
| `registerEvents(EventGroupRegistry)` | 注册事件组（见 [事件扩展](事件扩展)） |
| `registerClientEvents(EventGroupRegistry)` | 注册客户端事件组 |

### 配方

| 钩子 | 作用 |
|---|---|
| `registerRecipeNamespaces(RecipeNamespaceRegister)` | 注册配方命名空间（handler 类） |
| `registerRecipeSchemas(RecipeSchemaRegister)` | 注册配方 schema（Java 端） |
| `registerRecipeLifecycleHooks(RecipeLifecycleRegister)` | 注册配方生命周期钩子 |

### Probe / 工作区

| 钩子 | 作用 |
|---|---|
| `registerProbeGenerator(ProbeRegistry)` | 替换内置 probe 生成器（只允许一个第三方） |
| `modifyWorkspaceConfig(...)` | 修改自动生成的 jsconfig.json |
| `registerScriptCompilers(...)` | 注册自定义脚本编译器（新语言前端） |
| `registerScriptProperty(...)` | 注册自定义脚本属性（`// key:`） |

### 附加数据

| 钩子 | 作用 |
|---|---|
| `attachServerData(...)` / `attachLevelData(...)` / `attachPlayerData(...)` | 给 Server/Level/Player 挂 `AttachedData` |

## 注册绑定（registerBinding）

`BindingRegistry` 按 `ScriptType` 注册。绑定分两类：

### 简单绑定：`register(name, value)`

```java
@Override
public void registerBinding(BindingRegistry registry) {
    registry.register("MyHelper", new MyHelperJS());

    // 限定脚本类型
    registry.register(ScriptType.CLIENT, "ClientHelper", new ClientHelperJS());

    // 直接绑 Java 类（脚本里能当构造器用）
    registry.register("MyItemHelper", MyItemHelper.class);
}
```

### 组合绑定：`BindingComposer`（helper + 原版类）

如果你的绑定既要 helper 方法又要暴露一个 MC 类的静态成员，用 `BindingComposer`：

```java
import com.tkisor.nekojs.api.data.BindingComposer;

@Override
public void registerBinding(BindingRegistry registry) {
    registry.register(BindingComposer.of("MyBlock", ScriptType.STARTUP, ScriptType.SERVER, ScriptType.CLIENT)
        .helper(new MyBlockHelperJS())       // helper 方法
        .delegate(net.minecraft.world.level.block.Block.class)  // MC Block 类静态成员
        .typeOverride(MyBlockHelperJS.class)  // .d.ts valueType（避免 preflight 误报）
        .build());
}
```

> 旧版的 `DelegatingBinding` 已泛化为 `BindingComposer`。`Item` 绑定就是它的第一个用户。

## Binding 接口

如果想完全自定义绑定行为，实现 `Binding` 接口（`SimpleBinding`/`TypedBinding` 是内置 record）：

```java
public interface Binding {
    String name();
    Object value();
    Class<?> valueType();          // 默认 value.getClass()；代理类要显式声明
    default void close(ScriptType) {}  // reload/close 时的清理钩子
}
```

`valueType()` 对 `ProxyObject`/动态成员绑定的很关键——preflight 校验器和 probe 都靠它知道绑定有哪些成员，避免反射不到动态成员时误报。

## 声明性 descriptor（provides）

在 `@RegisterNekoJSPlugin.provides` 里声明你提供的 bindings/events/adapters：

```java
@RegisterNekoJSPlugin(provides = {
    @ProvidesBinding(name = "MyHelper", scriptTypes = { ScriptType.SERVER }),
    @ProvidesEventGroup(name = "MyEvents"),
    @ProvidesAdapter(targetType = ItemStack.class)
})
```

**作用**：
1. **冲突检测**：两个插件都 `@ProvidesBinding(name="MyHelper")` → 启动时报错，列出两个插件 id。
2. **probe 种子**：provides 列表可以预种子 catalog，加速 probe。
3. **元数据**：未来 addon 市场可不加载 jar 就读 descriptor。

descriptor **不替代代码**——你仍要实现 `registerBinding` 真正注册绑定。descriptor 只是声明层。

## 类型文档

两种等价方式给绑定的方法/字段加文档（probe 会生成进 `.d.ts`）：

### 注解式（推荐，Java 源码内联）

```java
import com.tkisor.nekojs.api.annotation.*;

public class MyHelperJS {
    @Doc("把两个数字加起来")
    @Example("MyHelper.add(1, 2)  // 3")
    public int add(
        @Param(name = "a", desc = "第一个数") int a,
        @Param(name = "b", desc = "第二个数") int b
    ) {
        return a + b;
    }
}
```

详见 [注解体系](注解体系)。

### 编程式（TypeDocsRegister，用于第三方/动态场景）

```java
@Override
public void registerTypeDocs(TypeDocsRegister docs) {
    docs.method(MyHelperJS.class, "add")
        .description("把两个数字加起来")
        .param("a", "第一个数")
        .param("b", "第二个数");
}
```

bootstrap 时 `AnnotatedTypeDocsCollector` 会反射 `@Doc`/`@Param` 等注解转成 `TypeDocCatalogEntry` 灌进 `TypeDocsRegister`，与编程式注册的合并。**单一真相源是 `TypeDocsRegister`**。

## 跨平台插件

如果你的插件要支持多个平台：
- **抽象 MC 类型**：尽量用 common 的抽象（`NekoId` 而非 `Identifier`/`ResourceLocation`）。
- **平台专属代码**：放各自的 sourceSet（`platforms/<platform>/...`），用 `Platform.capabilities()` feature-gate。
- **`requiredMods`**：用注解的 `requiredMods` 控制平台相关加载。

## Gradle 依赖

插件 mod 的 `build.gradle` 里加：

```groovy
dependencies {
    compileOnly 'curse.maven:graal-1504336:7983197'   // Graal 前置
    // compileOnly 引入 NekoJS（等 :common-api 拆分后用 api jar；当前用 common jar）
    compileOnly files('libs/nekojs-1.1.0-preview1.jar')
}
```

> 注：NekoJS 正在拆 `:common-api` / `:common-impl`（见 `ai_arch/long-term-api-design.md`）。拆分完成后插件只 `compileOnly` 依赖 `:common-api` jar，不接触内部包。

## 测试你的插件

1. 把你的插件 mod 和 NekoJS + Graal 一起放进 `mods/`。
2. 启动游戏，看日志确认插件被发现（搜你的插件类名）。
3. 在脚本里调用你注册的绑定。
4. 跑 `/nekojs probe`，检查 `.d.ts` 里有没有你的绑定的声明（含 `@Doc`）。
