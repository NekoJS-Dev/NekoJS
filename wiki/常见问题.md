# 常见问题

## 安装与启动

### Q: 启动游戏崩溃，提示找不到 GraalJS / polyglot

A: 没装或装错版本的 **Graal** 前置 mod。NekoJS 依赖 Graal 提供 GraalJS 运行时。去 [Graal 的 CurseForge 页面](https://www.curseforge.com/minecraft/mc-mods/graal) 下载与你 MC / 加载器版本**完全匹配**的版本。当前要求 Graal 25.1.3.6+。

### Q: `nekojs/` 文件夹没生成

A: 首次启动后会在游戏根目录生成。如果没生成：
1. 确认 NekoJS 和 Graal 都正确加载了（看 `mods/` 和启动日志）。
2. 检查游戏目录权限。
3. 试试手动运行 `/nekojs probe`，它会触发工作区生成。

### Q: 支持哪些 MC 版本？

A: 见 [Home - 支持的 Minecraft 版本](Home#支持的-minecraft-版本)。当前支持 NeoForge 26.1 / 26.2 / 1.21.1 与 Cleanroom 1.12.2。

## 脚本运行

### Q: 我的脚本没生效

A: 逐项排查：
1. 文件放对目录了么？（`startup_scripts` / `server_scripts` / `client_scripts` / `test_scripts`）。见 [脚本基础](脚本基础)。
2. 扩展名对么？（`.js`/`.mjs`/`.cjs`/`.ts`/`.jsx`/`.tsx`）。
3. 脚本被 `// disable:` 禁用了么？见 [脚本属性](脚本属性)。
4. `// modloaded:` 列的 mod 都装了么？
5. 服务端/客户端脚本改了有没有 `/nekojs reload`？
6. 启动脚本注册的内容（新物品/方块）改了**重启游戏**了么？
7. 跑 `/nekojs error` 看有没有错误。

### Q: 报错 `事件X is not defined` / `XXX is not a function`

A: 多半是脚本类型不对或事件名拼错：
- 服务端事件（如 `ServerEvents.recipes`）必须在 `server_scripts/` 里写。
- 客户端事件（如 `ClientEvents.tick`）必须在 `client_scripts/`。
- 事件名查 [事件参考](事件参考)，绑定名查 [全局绑定](全局绑定)。

### Q: reload 后旧代码还在跑 / 行为没变

A:
- **共享状态**：`global` 是进程级的，reload 后依然存活。如果你改的是 `global` 上的数据结构，可能需要手动清理。
- **事件监听器**：reload 会清除旧监听器，但如果之前注册时出了问题，监听器可能没清干净。再 reload 一次。
- **配方（NeoForge）**：NeoForge 支持配方热重载（`RecipeManagerMixin` 从缓存重建配方，服务端即时生效）；JEI/REI 配方面板可能需要客户端刷新。详见 [命令 - 配方 reload](命令#配方-reload-的平台差异)。
- **注册表（startup）**：启动脚本注册的内容 reload 不会真正加进游戏，需重启。

### Q: 顶层 await / dynamic import 报错

A: 确认你的文件被当 ESM 处理：
- 用 `.mjs` 扩展名最稳妥。
- 或确认 `engine.toml` 里 `enableEsmAuthoring = true`（默认开）。
- 顶层 await 只能在 ESM 模块里用，不能在 CJS（`.cjs`）里用。

## TypeScript / JSX

### Q: 我的 `enum` / `namespace` 报错

A: NekoJS 的 TS 前端**已支持** `enum`/`const enum`（编译为运行时对象）和 `namespace`/`module`（编译为 IIFE）。如果遇到具体语法不支持，请提交 issue。

### Q: `.ts` 文件没有类型检查

A: TS 前端只擦除不检查。检查靠 IDE（VS Code）配合 `.neko_probe` 类型声明。跑 `/nekojs probe` 刷新类型声明。`.js` 文件可在顶部加 `// @ts-check` 开启检查。

### Q: 如何使用 automatic JSX runtime？

A: 在 `nekojs/config/engine.toml` 设置 `jsxAutomaticRuntime = true`，并在 `nekojs/` 工作区内将 `jsx-runtime.js` 放在裸模块解析路径 `node_modules/nekojs/jsx-runtime.js`。它必须导出标准的 `jsx`、`jsxs` 和 `Fragment`：编译结果将子节点传入 `props.children`，单/零子节点使用 `jsx`，多子节点使用 `jsxs`，片段把 `Fragment` 作为 type。

自动生成的 `jsconfig.json` 仍是 classic 默认设置。若要让 IDE 使用 automatic JSX，请手动维护配置为 `"jsx": "react-jsx"`、`"jsxImportSource": "nekojs"`，且不要设置 `jsxFactory` / `jsxFragmentFactory`。外部生成器可调用 `JSConfigModel#useAutomaticJsxRuntime()` 生成同一组字段；NekoJS 不会通过 WorkspaceGenerator 或平台生命周期自动改写它。

## 配方

### Q: 我加了配方但配方面板（JEI/HEI）里没有

A:
- **NeoForge**：`/nekojs reload` 会重跑配方脚本并从缓存重建配方（服务端合成逻辑即时生效）；JEI/REI 配方面板可能需要客户端刷新（如重进世界或面板刷新）。详见 [命令](命令)。
- **Cleanroom 1.12.2**：支持完整热重载，reload 后会自动刷新 HEI/JEI。如果没刷新，确认你装的是 HEI（`had-enough-items`）而不是别的。

### Q: `event.recipes.create.mixing(...)` 报错

A: 这个类型没有 handler 也没有 schema。要么：
1. 用原始 JSON：`event.custom({ type: 'create:mixing', ... })`。
2. 给它写一个数据驱动 schema JSON（见 [配方系统 - 数据驱动 Schema](配方系统#数据驱动-schema)），之后就能用位置参数了。

### Q: 配方 id 是什么？怎么指定？

A: 每个配方有唯一 id（如 `minecraft:stone`）。`.id('yournamespace:name')` 指定；不指定则自动生成 `nekojs:<prefix>_<hash>`。用 `event.ids()` 列所有 id，用 `event.get(id)` 按 id 取，用 `event.removeById(id)` 按 id 删。

## 注册内容

### Q: 我注册的物品没有材质 / 显示紫黑方块

A: 缺资源文件。注册的物品默认按原版资源路径解析：
- 材质：`nekojs/assets/<mod>/textures/item/<name>.png`
- 模型：`nekojs/assets/<mod>/models/item/<name>.json`

在 `nekojs/assets/` 下放对应文件即可。详见 [注册新内容 - 资源与本地化](注册新内容#资源与本地化)。

### Q: 注册的物品名字显示为 `item.mymod.xxx`

A: 缺语言文件。在 `nekojs/assets/<mod>/lang/zh_cn.json` 加：
```json
{ "item.mymod.xxx": "中文名" }
```

### Q: reload startup 后我加的物品没出现

A: 启动脚本注册的内容**必须重启游戏**。`/nekojs reload startup` 只重跑脚本逻辑，注册表已冻结。详见 [脚本基础](脚本基础)。

## 模块 / npm

### Q: `require('xxx')` 报错 `module not found`

A:
1. 包放进 `nekojs/node_modules/<包名>/` 了吗？
2. 包是**纯 JS** 的吗？原生 bindings（C/C++ 编译）**不支持**。
3. 路径对吗？`require('./xxx')` 相对当前文件；`require('xxx')` 走 node_modules。

### Q: 我想用某个 npm 包但它是原生 bindings

A: 不支持。换纯 JS 的替代品，或自己用 `java:` 导入 Java 等价物实现。

### Q: `java:java/lang/Integer` 这种导入语法对吗？

A: 对。规则：`java:` 前缀 + 斜杠分隔路径。详见 [模块系统 - 导入 Java 类](模块系统#导入-java-类javav-模块)。

## IDE / 类型提示

### Q: VS Code 没有补全

A:
1. 跑 `/nekojs probe` 生成 `.neko_probe/`。
2. 用 VS Code **打开 `nekojs/server_scripts/`（或对应目录）作为根**，而不是整个游戏目录。这样 `tsconfig.json` 才能正确关联 `.neko_probe`。
3. 确认 `.neko_probe/` 在游戏根目录（与 `nekojs/` 同级）。

### Q: 补全的类型和实际运行不一致

A: 跑 `/nekojs probe` 重新生成。如果你是新加了 mod 或注册了新内容，类型声明会过期。这是已知限制（probe 是手动触发的）。

## 性能

### Q: 我的 tick 事件很卡

A: `ServerEvents.tickPre`/`tickPost` 每 tick（50ms）都跑。脚本里别做重活（大量文件 IO、复杂循环）。耗时操作考虑缓存、节流、或用 `setTimeout`/计数器降频。

### Q: 脚本加载很慢

A: NekoJS 用 GraalJS，首次加载有预热成本。运行起来后很快。如果持续慢，检查是不是在加载大量 npm 依赖或在顶层做了重 IO。

## 安全

### Q: 我的脚本访问文件被拒

A: 沙盒限制——只能访问游戏目录内。详见 [Node.js 兼容 - 访问范围限制](Node-js-兼容#访问范围限制)。如需放宽（仅单人/可信环境），看 `nekojs/config/engine.toml`。

### Q: 多人服务器用 NekoJS 安全吗？

A: 脚本应视为**可信代码**。沙盒限制了 Java 类访问和文件范围，但如果你开了远程脚本同步（NetworkEvents + `ScriptSyncService`），客户端能同步脚本到服务器，需要你信任连接的玩家。

## 还没解决？

- 查 [事件参考](事件参考)、[全局绑定](全局绑定)、[配方系统](配方系统) 确认 API 用法。
- 查仓库 `docs/ROADMAP.md` 了解哪些是已知限制/未来计划。
- 提 issue（见仓库 README 链接）。
