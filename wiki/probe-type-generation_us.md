# Probe type generation

> Probe is NekoJS's built-in **type declaration generator**, equivalent to ProbeJS. It reflects Java classes in a running instance, generates `.d.ts` for **TypeScript** and a `.pyi` stub package for **Python**, and configures editors for code completion.
>
> Two backends are built in: `typescript:builtin` and `python:builtin`, registered by common's `NekoProbeBuiltinPlugin`. Third-party plugins can register their own backends through `registerProbeBackends`.

<a id="wiki-section-2"></a>
## Commands

| Command | Purpose |
|---|---|
| `/nekojs probe` | With no arguments, runs only the built-in TS backend (`typescript:builtin`) |
| `/nekojs probe <语言>` | Run the language's default backend. `languages.<lang>.backend` takes precedence; otherwise, select the highest-priority backend for that language. For example, `/nekojs probe python`. |
| `/nekojs probe <语言> <名字>` | Select an exact backend, for example `/nekojs probe typescript builtin` |
| `/nekojs probe all` | Run **all** registered backends across languages |
| `/nekojs probe list` | List registered backends, for example `typescript:builtin (NekoJS (built-in))` |
| `/nekojs probe reload` | Discard the probe.toml configuration cache and reread from disk next time; configuration changes do not require a restart |
| `/nekojs probe enable` / `disable` | **Persist** `enabled` in probe.toml and reload the cache |
| `/nekojs probe reset_config` | Remove editor configuration generated by each backend (jsconfig/pyrightconfig/snippets), rebuild default configuration, and immediately rerun the default TS probe. Use it to restore a manually damaged jsconfig. |

`<语言>` and `<名字>` support TAB completion. All probe subcommands run on the server thread and require the same permission as `/nekojs` (op 2+).

**jsconfig merge semantics**: each probe run **refreshes only probe-managed entries**: `java:*` / `@side-only/*` path aliases, include/typeRoots entries pointing into `.neko_probe/`, and JSX runtime keys. **Manually added entries and other keys remain unchanged**. For example, your `./typings/custom.d.ts` include or custom typeRoots entries are not overwritten.

<a id="wiki-section-3"></a>
## Workflow

When a user runs `/nekojs probe`, `ProbeCoordinator` coordinates a shared collection pass for multiple backends:

```text
1. Shared collection (collectClasses)
   ├─ Seeds: event types, dispatch key types, binding Java types (including proxy extraDocTypes)
   └─ BFS reachable closure; depth = probe.toml scan.maxDepth (default 5), filtered by scan settings
     (SMART uses include allowlists + forceScanMods; FULL allows everything except exclusions; NONE fails)

2. Shared IR (built on demand)
   ├─ Trigger: probe.modifyType / probe.assignType has listeners, or a selected backend requiresIr
   │  (both built-in TS and Python backends use requiresIr=true; IR is the only rendering source)
   ├─ TypeReflector reflects collected classes in parallel → List<TypeDecl> (reflection failures are skipped)
   ├─ Apply probe.assignType first (global type redirection, marking affected classes mutated)
   └─ Then fire probe.modifyType (parameter-level edits; explicit edits are not overwritten by assign)

3. Collect probe.addGlobal / probe.snippets only when each has listeners

4. Render each selected backend sequentially: render output to memory (no disk writes) → default generate
   synchronizes files in place under <baseDir>/<language output subdirectory>:
   skip identical content, overwrite changed content, remove files no longer generated
   ├─ Render failure → no disk changes, old output retained; escaping paths (absolute paths/..) rejected
   └─ File locked by another process → retry with backoff; report the filename if retries fail
      (failure to remove a stale file only warns)

5. Editor configuration contributions (each backend supplies fragments, merged idempotently)
   ├─ TS: merge paths / include / typeRoots into each script directory's jsconfig.json
   │  (pointing to .neko_probe/typescript/)
   ├─ Python: merge extraPaths into each directory's pyrightconfig.json (pointing to .neko_probe/python),
   │  and inject python.analysis.extraPaths / python.languageServer into its .vscode/settings.json
   │  through the common contribution mechanism (see Python completion)
   └─ Snippets (TS only): merge into nekojs/.vscode/nekojs.code-snippets
```

## Output layout

The following layouts are **actual output from the built-in backends**, not formats imposed by probe. The mechanism only requires `render` to return a map of relative paths to text; backends choose their own paths. Directories are configurable through `[languages.<id>].outputDir` in `probe.toml`.

<a id="wiki-section-5"></a>
### TypeScript (default `.neko_probe/typescript/`)

```text
.neko_probe/typescript/
├── @package/                       # Java class declarations mirroring package directories
│   ├── index.d.ts                  # Top-level package re-exports
│   ├── com/tkisor/nekojs/.../index.d.ts
│   └── net/minecraft/.../index.d.ts
├── @side-only/
│   ├── startup/{events,bindings}/index.d.ts
│   ├── server/{events,events/recipes,bindings}/index.d.ts
│   └── client/{events,bindings}/index.d.ts
├── @special/
│   ├── index.d.ts                  # export * as types from "@special/types"
│   └── types/index.d.ts            # Registry literals, such as a union of all item ids
├── @manual/
│   ├── index.d.ts                  # Manual .d.ts declarations
│   └── globals.d.ts                # declare const output from probe.addGlobal, when listeners exist
├── @nekojs/managed/<side>/index.d.ts  # Managed API declarations
└── jsconfig.json                   # Internal resolution configuration
```

<a id="wiki-section-6"></a>
### Python (default `.neko_probe/python/nekojs/`)

```text
.neko_probe/python/nekojs/
├── __init__.pyi    # Global bindings + event group entries + probe.addGlobal globals
│                  # (target of `from nekojs import *`, bounded by __all__)
├── py.typed        # PEP 561 marker (empty file)
├── README.md       # Usage instructions
├── _java/          # Java type stubs grouped by Java package; ancestor packages have namespace markers
│   └── net/minecraft/.../__init__.pyi
└── _events/        # Event declarations grouped by script side
    ├── __init__.pyi
    └── server/__init__.pyi
```

<a id="wiki-section-7"></a>
### Editor path mapping (TS)

Probe **automatically merges** `jsconfig.json` in each `*_scripts/` directory, refreshing probe-owned keys and preserving user-defined keys. It maps paths to `.neko_probe/typescript/`:

```json
{
  "compilerOptions": {
    "paths": {
      "java:*":        ["../../.neko_probe/typescript/@package/*"],
      "@side-only/server":    ["../../.neko_probe/typescript/@side-only/server"],
      "@side-only/server/*":  ["../../.neko_probe/typescript/@side-only/server/*"],
      "@special":      ["../../.neko_probe/typescript/@special"],
      "@special/*":    ["../../.neko_probe/typescript/@special/*"]
    }
  }
}
```

> Relative paths are calculated from the script and output directories. Each script type (startup/server/client/test) maps its own `@side-only/<side>`.

<a id="wiki-section-8"></a>
## probe.toml configuration

Configuration lives in `<game>/nekojs/config/probe.toml`. On first load, defaults and comments are written as needed through `CommentedFileConfig` + autosave. A damaged or invalid file falls back to defaults. `/nekojs probe reload` rereads it without a restart.

| Key | Default | Semantics |
|---|---|---|
| `enabled` | `true` | Master switch. `false` makes probe immediately return failure (`"probe disabled in probe.toml"`). `/nekojs probe enable|disable` changes this key. |
| `runAtStartup` | `false` | Automatically run the default TS probe once when the server starts (ServerStarted, equivalent to `/nekojs probe`). A summary is logged and failure does not prevent startup. Enable it to avoid running the command manually each time. |
| `baseDir` | `".neko_probe"` | Output base directory, relative to the game directory. Each language backend owns `<baseDir>/<language>`, such as `.neko_probe/typescript`. |
| `scan.includePackages` | `[]` | Allowlist of class-scanning package rules. An entry is a **literal package prefix** (`fqn` starts with `prefix.`) or a **`re:` regex** such as `re:com\.example\..*\.api\..*`, matched against the complete fully qualified name. **Replacement semantics**: a non-empty list **fully replaces** the default allowlist (`java`, `com.tkisor.nekojs`, and platform-default Minecraft/loader packages). To **append**, use `extraIncludePackages`, not a copy of the defaults here. |
| `scan.extraIncludePackages` | `[]` | Append to the effective allowlist; **append semantics**, also supporting literal prefixes and `re:` regexes. Useful for adding `com.mojang` or a mod package. |
| `scan.excludePackages` | `[]` | Denylist rules supporting literal prefixes and `re:` regexes. **Always applied**, including in FULL mode; matching classes are skipped. |
| `scan.forceScanMods` | `["minecraft"]` | Mod ids or package rules **forced into** scanning outside the allowlist. Built-in mappings: `minecraft` → `net.minecraft`, `neoforge` → `net.neoforged`, `forge` → `net.minecraftforge`, `java` → `java`. An entry containing `.` is a literal prefix; one starting with `re:` is a regex. Unknown mod ids are logged at debug and ignored. excludePackages still takes precedence over forced inclusion. |
| `scan.maxDepth` | `5` | Maximum BFS depth from event/binding seeds; values ≤0 fall back to 5 |
| `scan.mode` | `"SMART"` | `SMART`: allowlist + forceScanMods filtering. `FULL`: skip the include allowlist; closure is constrained only by excludes and maxDepth. `NONE`: no scanning, and probe returns failure. Unknown values fall back to `SMART`. |
| `languages.<lang>.outputDir` | Language id itself | The language output's **subdirectory** under `baseDir`, such as default `typescript` → `.neko_probe/typescript`. Missing/null falls back to the language id. The default `ProbeBackend.outputDir` checks this key first. |

> **Regex package rules**: entries in `includePackages` / `extraIncludePackages` / `excludePackages` / `forceScanMods` can be literal package prefixes (the old behavior, `fqn.startsWith("prefix.")`) or `re:<pattern>` regexes matching the **entire** class FQN. For example, `re:com\.example\.(mod1|mod2)\..*` includes several mod packages at once. Compiled regexes are cached, avoiding extra work on the scanning hot path. An invalid regex warns once and never matches.

| `languages.<lang>.backend` | Unset | Preferred backend name for `/nekojs probe <lang>`; unset or unknown names fall back to the language registry default, the highest-priority backend |

> Defaults include `languages.typescript.outputDir = "typescript"` and `languages.python.outputDir = "python"`, written on first load so directory names match language ids. The `languages` table is parsed dynamically for arbitrary ids and also supports third-party backend languages.

Example: append a mod package, exclude a debug package, and increase depth:

```toml
enabled = true
baseDir = ".neko_probe"

[scan]
extraIncludePackages = ["com.example.mymod", "com.mojang"]
excludePackages = ["com.example.mymod.debug"]
maxDepth = 6
mode = "SMART"

# Per-language options: change the default backend or output subdirectory
[languages.typescript]
backend = "my-better-ts"     # Unset → language registry default (highest priority)
outputDir = "typescript"     # Unset → language id itself
```

## probe.* events

The `ProbeEvents` group has 4 events, **all for SERVER scripts**. Probe commands run on the server thread, so register listeners at top level in `server_scripts`:

| Event | Event object | Timing/purpose |
|---|---|---|
| `modifyType` | `ProbeModifyTypeEventJS` | **Before** type rendering, after IR construction: edit reflected `TypeDecl` at parameter level. Marked classes are rendered directly from the edited IR. |
| `assignType` | `ProbeAssignTypeEventJS` | Global type redirection: replace a Java FQN **everywhere** with a custom type. Applied after IR construction by replacing SYMBOL type slots; affects TS (rerendering touched classes) and Python. |
| `addGlobal` | `ProbeAddGlobalEventJS` | Register extra global declarations (name + type). TS → `@manual/globals.d.ts` (`declare const Name: T;`); Python → `nekojs/__init__.pyi`. |
| `snippets` | `ProbeSnippetEventJS` | Register VSCode `.code-snippets` entries. Currently consumed only by TS, merged into `nekojs/.vscode/nekojs.code-snippets`; probe-owned snippet names are replaced and user snippets are retained. |

> Shared IR is built once if any selected backend requires it (both built-in TS/Python backends use requiresIr=true) or if `modifyType` / `assignType` has listeners. All backends reuse the same edited IR.

All type parameters to editing/declaration methods accept:
- **Strings**: containing `.` means a Java FQN (SYMBOL); otherwise a raw type name such as `"string"` / `"number"` / `"boolean"` / `"int"`.
- **ApiTypeRef**: constructed through `event.type(desc)` / `event.array(element)` / `event.union(a, b, ...)`.

<a id="wiki-section-10"></a>
### modifyType example

```javascript
// server_scripts/probe_patch.js
ProbeEvents.modifyType(event => {
  const editor = event.forClass("net.minecraft.world.entity.player.Player")
  if (editor) {
    editor
      .renameMethod("getXxx", "getCustom")                          // Rename every overload with the same name
      .changeParamType("addItem", 0, "net.minecraft.world.item.ItemStack")  // Change parameter type by index
      .markOptional("eat", "level")                                  // Make the TS parameter optional: name?: type
      .setMethodDoc("getCustom", "Custom documentation")
      .addParam("eat", "priority", "number")                         // Append to every same-named overload
      .setDoc("Player extensions")
  }
  // Type construction helpers:
  const arr = event.array("string")                 // string[]
  const u   = event.union("string", "number")       // string | number
  editor.changeReturnType("getCustom", u)
})
```

<a id="wiki-section-11"></a>
### ClassEditor methods

Operations by name affect **all same-named** methods/constructors, including overloads, in that class. A missing target is a **silent no-op** with DEBUG logging; check `hasMethod` / `hasField` first if needed. Any edit marks its `TypeDecl` as mutated.

| Level | Method | Description |
|---|---|---|
| Class | `hide()` | Hide the entire class, rendering an empty declaration |
| Class | `setDoc(doc)` | Replace class documentation (JSDoc) |
| Class | `renameClass(newName)` | Rename the class in TS/Python output to newName; enum self-references are renamed too |
| Class | `changeSuper(type)` | Change the superclass type |
| Method | `hasMethod(name)` | Check for a method, including constructors |
| Method | `renameMethod(name, newName)` | Rename all same-named overloads |
| Method | `hideMethod(name)` | Hide all same-named overloads |
| Method | `setMethodDoc(name, doc)` | Replace method documentation |
| Method | `changeReturnType(name, type)` | Change the return type |
| Method | `changeParamType(name, index, type)` | Change parameter type by index in every same-named overload with that index |
| Method | `changeParamType(name, paramName, type)` | Change parameter type by name |
| Method | `renameParam(name, paramName, newName)` | Rename a parameter by name |
| Method | `removeParam(name, index)` | Remove a parameter by index |
| Method | `markOptional(name, paramName)` | Mark a parameter optional in TS |
| Method | `addParam(name, paramName, type)` | Append a parameter to the method |
| Method | `addMethod(name, returnType, ...paramSpecs)` | Add an instance method. Each `paramSpecs` entry is `"type"` (automatic arg0/arg1 names) or `"name:type"`. |
| Method | `addStaticMethod(name, returnType, ...paramSpecs)` | Add a static method, with the same semantics as `addMethod` |
| Field | `hasField(name)` | Check for a field |
| Field | `renameField(name, newName)` | Rename a field |
| Field | `hideField(name)` | Hide a field |
| Field | `changeFieldType(name, type)` | Change the field type |
| Field | `setFieldDoc(name, doc)` | Replace field documentation |

<a id="wiki-section-12"></a>
### assignType example

```javascript
ProbeEvents.assignType(event => {
  // Replace net.minecraft.nbt.CompoundTag with your custom JS type in every declaration
  event.assign("net.minecraft.nbt.CompoundTag", "MyNbt")
})
```

`assign(javaFqn, typeDesc)` registers the mapping. Semantically, assign changes reflected types; an explicit type edit in `modifyType` takes precedence afterward.

<a id="wiki-section-13"></a>
### addGlobal / snippets example

```javascript
ProbeEvents.addGlobal(event => {
  event.add("MyFlag", "boolean")                       // → declare const MyFlag: boolean;
  event.add("Helper", "com.example.Helper")            // → SYMBOL reference (imports collected automatically)
})

ProbeEvents.snippets(event => {
  event.add("nekojs-listener", "listen", "ServerEvents.started(e => { $1 })",
            "Listen for server startup")
})
```

## Python completion

`/nekojs probe python` generates the `.neko_probe/python/nekojs/` stub package (PEP 484/561), allowing pyright / Pylance / Jedi to provide completion for Python scripts:

1. Add the magic import at the top of your script: `from nekojs import *`. **The transpiler strips it**, producing no JS and leaving source mapping unaffected. It exists only for the type checker.
2. pyright resolves the stub package through `extraPaths`. NekoJS automatically merges `.neko_probe/python` into the `extraPaths` of multiple `pyrightconfig.json` files, idempotently and without duplicates: the game root, `nekojs/`, each script root, and every nested directory under a script root that actually contains `.py` files. The same directories' `.vscode/settings.json` receive these keys through the common injection mechanism:
   - `python.analysis.extraPaths`: the same paths, appended with string deduplication.
   - `python.languageServer`: set to `"Pylance"` only if the user has not explicitly chosen one. VSCode's `"Default"` may fall back to Jedi in some environments, and Jedi does not read pyrightconfig/extraPaths, resulting in no completion.

   **Pylance reads configuration only at the workspace root**, whereas pyright CLI discovers configuration upward from source files. Open the game directory, `nekojs/`, a script directory, or a nested directory containing `.py` files directly in your editor, not their parent directory. NekoJS generates configuration for each of these possible workspace roots.
3. Completion contents:
   - `nekojs/__init__.pyi`: global bindings, event group entries, and globals from `probe.addGlobal`; `__all__` defines exports for `from nekojs import *`.
   - `nekojs/_java/<java.包>/__init__.pyi`: Java type stubs. Generics flatten to `Any`, while member names, parameter counts, and field types are retained for everyday completion.
   - `nekojs/_events/<side>/__init__.pyi`: event declarations by script side.
   - `nekojs/py.typed`: PEP 561 marker; `nekojs/README.md`: usage instructions.
4. Adapter input aliases: `<Simple>_ = <Simple> | <input types>`, such as `ItemStack_ = ItemStack | str | ...`, corresponding to TS `$Foo_`. Only target classes present in the IR receive aliases; unmappable shapes such as registry/raw TS fragments are skipped.

> Python backend `requiresIr()` always returns true. Selecting Python, including through `/nekojs probe all`, makes the coordinator build shared IR. `modifyType` / `assignType` edits therefore affect Python output too.

<a id="wiki-section-15"></a>
## TS completion (automatic jsconfig merging)

After generating output, probe **idempotently merges** the following settings into each script directory's `jsconfig.json` and `.neko_probe/jsconfig.json`, all pointing to `.neko_probe/typescript/`:

- `compilerOptions.paths`: `java:*`, `@side-only/<env>`, `@side-only/<env>/*`, `@special`, `@special/*`
- `include`: `@package/**/*.d.ts`, `@manual/**/*.d.ts`, `@side-only/<env>/**/*.d.ts`, `@nekojs/managed/<env>/**/*.d.ts`
- `typeRoots`: `<tsOut>/@package`, `../node_modules/@types`

Merge rules: replace probe-owned keys with current values and **retain user-defined keys**. Managed JSX keys follow engine configuration and are reconciled; unrelated user settings remain intact. See [TypeScript and JSX](typescript-and-jsx_us).

## Naming conventions in built-in TS output

The table below describes directory and naming conventions used by the built-in TypeScript backend. **Probe does not enforce these names**. They are listed because two consumers depend on them: script module specifiers such as `import type ... from '@side-only/server/events'`, and aliases merged by probe into `jsconfig.json`.

| Name | Meaning |
|---|---|
| `@package/` | Java package directory mirror |
| `@side-only/<side>/` | Grouping by script side (startup/server/client) |
| `@special/types/` | Registry literal unions, including all item ids and tag ids |
| `@manual/` | Handwritten plugin/platform `.d.ts`, plus `globals.d.ts` |
| `$ClassName` | Class declaration naming convention, avoiding JS keywords |
| `$Foo_` | Adapter input alias, where `Foo` is the target type name |
| `java:` / `@side-only` / `@special` | Module specifier prefixes |

The constraints are conditional, not universal:

- **A backend for a new language**, such as Lua, a JSON inventory, or a documentation site, has no relationship to this table and can organize output freely.
- **A replacement TypeScript backend reusing existing editor configuration** can keep these names and require no other changes.
- **A replacement TypeScript backend with a custom layout** is allowed, but requires two editor integration changes or `@side-only/...` in scripts cannot resolve. First is the backend's `contributeEditorConfig`, which merges aliases into `jsconfig.json` after probe. Second is the plugin hook `NekoJSPlugin.modifyWorkspaceConfig`: `WorkspaceGenerator` independently hardcodes the same aliases when creating the first workspace configuration, while `jsconfig.json` does not yet exist. Without changing it, configuration is wrong between initial startup and the first probe run. Existing scripts also hardcode these module specifiers, so changing layout is a breaking change for script authors.

<a id="wiki-section-18"></a>
## Data source: catalog snapshot

`NekoScriptCatalog.snapshot(runtime)` creates an immutable `NekoScriptCatalogSnapshot`. Backends consume only the snapshot, as pure functions of `(snapshot, collectedClasses, ir)`. This is the main decoupling point.

The snapshot contains:

- `bindings`: all global bindings (name + Java type)
- `events`: all groups/events (group + name + event type + cancellation + dispatch information)
- `adapters`: all adapters (target type + input forms)
- `recipeNamespaces`: recipe namespaces and handler method signatures
- `registryTypes`: registry literals used by `@special/types`
- `hostExtensions`: extension methods injected into vanilla classes
- `snippets`: IDE code snippets
- `typeDocs`: contents of `TypeDocsRegister` (descriptions/examples/parameter docs)
- `manualDeclarations`: handwritten `.d.ts`

<a id="wiki-section-19"></a>
## Supply data to probe (plugin authors)

<a id="wiki-section-20"></a>
### Bindings carry their types

`registry.register("Foo", new FooJS())` makes probe reflect public methods of `FooJS`. For JSDoc, annotate the class/methods/parameters with `@Doc` / `@Param` / `@Return` (`TypeReflector` consumes them), or use programmatic `registerTypeDocs` (`TypeDocsRegister.register(...)` / `registerManualDeclaration(...)`; see [Plugin development](plugin-development_us)).

<a id="wiki-section-21"></a>
### Registry literals

`NekoCatalogPlatformProvider.registryTypes()` supplies registry id lists. Probe generates `@special/types/index.d.ts`, including string literal unions of all item ids, so values such as `'minecraft:stone'` have completion.

Each registry also gets a tag union:

- `RegistryTypes.<名字>Tag`, such as `RegistryTypes.ItemTag`, contains tags bound in that registry at probe time. Adapters wrap it with `template("#", registryTag("Item"))` as <code>\`#${RegistryTypes.ItemTag}\`</code>, providing completion for `'#minecraft:planks'`. Empty sets, whether because the platform lacks tags or probe ran before tag binding, fall back to `string` to avoid template types becoming `never` and producing false errors.

There is also a registry-independent union:

- `RegistryTypes.Namespace` combines two sources: `NekoCatalogPlatformProvider.modIds()` (the loader mod list on all three platforms, including mods that registered nothing in this registry) and the `:` prefixes of all registry entry ids (including script-created namespaces such as `event.create('mymod:cool_gem')` and data-pack namespaces not owned by a mod). Adapters wrap it with `template("@", namespace())` as <code>\`@${RegistryTypes.Namespace}\`</code>, providing completion for `'@create'`. It is not divided by registry: a namespace's validity does not depend on which registry contains it. A filter with no matches simply returns an empty result, not an error.

<a id="wiki-section-22"></a>
### Manual declarations

`NekoCommonManualDeclarations` in common and platform manual declarations supply handwritten `.d.ts` fragments to `@manual/index.d.ts` for content reflection cannot express.

## Add a custom backend (developer guide)

Built-in `typescript:builtin` / `python:builtin` occupy those names. Third parties can **replace** an implementation by choosing the same language with a different `name`, or **add** a new output type through a new language id, such as Lua, a JSON inventory, or a documentation site.

<a id="wiki-section-25"></a>
### Minimal working example

A backend implements only `languageId()` / `name()` / `render(ctx)`. The following complete example exports collected classes as a JSON inventory:

```java
public final class JsonListBackend implements ProbeBackend {

    @Override
    public String languageId() {          // Language id, used by commands and the default output directory
        return "json";
    }

    @Override
    public String name() {                // Unique within a language; use another name to coexist with a built-in backend
        return "list";
    }

    @Override
    public Map<String, String> render(ProbeContext ctx) {
        // Return "path relative to output directory ('/' separated) → UTF-8 text"; never write to disk
        StringBuilder sb = new StringBuilder("{\"classes\":[\n");
        boolean first = true;
        for (Class<?> c : ctx.collectedClasses()) {      // Shared BFS classes, already filtered by configuration
            if (!first) sb.append(",\n");
            first = false;
            sb.append("    {\"fqn\": \"").append(c.getName()).append("\"}");
        }
        sb.append("\n]}\n");
        return Map.of("classes.json", sb.toString());
    }
}
```

Register it in your plugin's `registerProbeBackends` hook; see [Plugin development](plugin-development_us):

```java
@Override
public void registerProbeBackends(ProbeBackendRegistry registry) {
    registry.register(new JsonListBackend(), "my-addon");
}
```

`/nekojs probe json` then generates `.neko_probe/json/classes.json`. `/nekojs probe json list` selects it explicitly, and `/nekojs probe all` also includes it.

<a id="wiki-section-26"></a>
### render contract (the only required rendering method)

- Return a map of paths relative to the output directory (`/`-separated, such as `@package/net/minecraft/index.d.ts`) to UTF-8 text. **Do not touch disk**.
- Writing, stale-file cleanup, retries for locked files, and path validation (rejecting absolute paths and `..` segments) are handled by the interface's **default `generate()`**. You neither need to implement disk handling nor risk getting it wrong.
- If render throws, that backend is marked failed and its message appears in command output. Old output is retained in full.
- If a precondition is unmet, such as missing data, throw `IllegalArgumentException`; the message is shown to the user unchanged.

<a id="wiki-section-27"></a>
### Optional overrides

| Method | Default | When to override |
|---|---|---|
| `requiresIr()` | `false` | Return `true` when shared type IR is needed (`ctx.ir()`, language-neutral `TypeDecl` list including `probe.modifyType` / `assignType` edits). Both built-in TS/Python use this. |
| `priority()` | `0` | With multiple backends for a language, the highest becomes the default for `/nekojs probe <语言>` |
| `outputDir(paths, config)` | `<baseDir>/<语言id>`, overridable by `probe.toml [languages.<id>].outputDir` | Special directory layout |
| `contributeEditorConfig(...)` | Empty | Configure the IDE to recognize output, merging into jsconfig/pyrightconfig and similar files idempotently |
| `resetEditorConfig(...)` | Empty | Clean up editor settings you wrote when `/nekojs probe reset_config` runs |
| `generate(ctx)` | Render + disk output | **Normally do not override**. Custom disk output/stale cleanup/locked-file retries are error-prone; reserve this for exceptional requirements. |

<a id="wiki-section-28"></a>
### Rules

These three rules are enforced by code:

- Duplicate `(language, name)` registrations **fail bootstrap** at registry lock; the error lists conflicting registrants.
- Paths returned by `render` must be valid relative paths. Null, blank, unparseable keys, absolute paths, and `..` segments are rejected. The entire backend is marked failed without disk changes.
- If two selected backends have the same `outputDir` in one run, only the first runs; the others are skipped with a warning. A later backend would otherwise delete the earlier backend's files as stale. Use separate `outputDir` values for coexistence.

Two more items describe selection, not restrictions: for a language with multiple backends, `/nekojs probe <语言>` chooses the highest priority (overridable by `probe.toml [languages.<lang>].backend`); other backends can be run explicitly with `/nekojs probe <语言> <名字>`. See the naming-conventions section above for layouts when replacing TS.

<a id="wiki-section-29"></a>
## Current Probe limitations

> These are known boundaries to keep in mind.

1. **JSDoc coverage depends on annotations**: `@Doc` / `@Param` / `@Return` documentation and `@Remap` / `@RemapByPrefix` / `@HideFromJS` naming/visibility are implemented, consumed directly by `TypeReflector` with the same rules as the runtime Graal remapper. For unannotated classes, add JSDoc through programmatic `registerTypeDocs` or the `setDoc` family in `ProbeEvents.modifyType`.
2. **Event imports may grow excessively**: `EventDeclarationGenerator.collectImports` recurses without a depth limit and may pull in many unrelated classes; addressed in Phase C.
3. **Third-party parameter names degrade**: NekoJS modules compile with `-parameters`, configured centrally in root build.gradle, so their declarations use real names. Third-party jars compiled without `-parameters` and JDK classes (standard `java.*` class files lack MethodParameters attributes) still lack names. `TypeReflector`'s `isNamePresent` fallback emits `arg0` / `arg1` and so on.
4. **Version drift**: probe is manually triggered, so adding mods/registered content makes declarations stale. Run `/nekojs probe` again.
5. **Python stub generics flattening**: type variables render as `Any`, without generic parameter relationships. This is sufficient for everyday completion, not full typing.
