# 项目架构

> 本页面向**给 NekoJS 贡献代码、写插件 mod、或想理解内部实现**的开发者。脚本作者不需要读。
> 完整架构细节见仓库 `ai_arch/nekojs-architecture.md`。

## 总览

NekoJS 是一个基于 **GraalVM/GraalJS** 的多平台 Minecraft 脚本引擎。

```text
                  ┌─────────────────────────────────────────┐
                  │            脚本（JS/TS/JSX）             │
                  └────────────────────┬────────────────────┘
                                       │ GraalJS Polyglot Context
                  ┌────────────────────▼────────────────────┐
                  │           NekoJS 运行时                  │
                  │  ┌──────────────────────────────────┐   │
                  │  │ core/  编译前端 / 模块 / 沙盒      │   │
                  │  │ script/ 脚本生命周期 / reload     │   │
                  │  │ api/   公开 API / 扩展点          │   │
                  │  │ probe/ 类型声明生成               │   │
                  │  │ plugin/ 插件 bootstrap            │   │
                  │  └──────────────────────────────────┘   │
                  └────────────────────┬────────────────────┘
                                       │ 平台抽象 SPI（IPlatform）
                  ┌────────────────────▼────────────────────┐
                  │           平台实现                       │
                  │  NeoForge 26.x / 1.21.1 / Cleanroom 1.12 │
                  └─────────────────────────────────────────┘
```

## 模块结构

```text
NekoJS/
├── common/                  # 跨平台通用代码（273 Java 文件，无 MC 依赖）
│   └── src/main/java/com/tkisor/nekojs/
│       ├── api/             # 公开 API：插件接口、适配器、事件、catalog
│       ├── core/            # 运行时心脏：Graal Context、编译器、模块、Node shim
│       ├── script/          # 脚本管理：ScriptManager、reload、工作区
│       ├── probe/           # .d.ts 生成
│       ├── eventbus/        # 事件总线实现
│       ├── bindings/        # MC 无关绑定类
│       ├── platform/        # 平台抽象 SPI
│       └── ...
├── platforms/
│   ├── neoforge-26-shared/  # 26.1/26.2 共享源码集（非 Gradle 模块！）
│   ├── neoforge-26.1/       # Gradle 模块：MC 26.1
│   ├── neoforge-26.2/       # Gradle 模块：MC 26.2
│   ├── neoforge-1.21.1/     # Gradle 模块：MC 1.21.1（自包含 fork）
│   └── cleanroom-1.12.2/    # Gradle 模块：MC 1.12.2（Forge coremod）
├── settings.gradle          # 引入 common + 4 平台
└── gradle/neoforge-common.gradle  # 3 个 NeoForge 模块共享约定
```

> **重要**：`neoforge-26-shared` 不是 Gradle 模块，是纯源码目录，由 26.1/26.2 通过 `srcDir '../neoforge-26-shared/...'` 吸收。

详见 [构建系统](构建系统)。

## 三个核心子系统

### 1. 运行时（`core/`）

GraalJS Polyglot `Context` 的装配与生命周期：

- **`NekoSharedEngine`**：进程级单例 Graal `Engine`，所有 Context 共享。
- **`NekoCoreContext`**：不可变 record，打包 engine + sandboxConfig + classFilter + errorTracker。
- **`NekoSandboxFactory`**：ContextBuilder，每 ScriptType 构建一个 Context。设 `HostAccess`、`ClassFilter`、IO（jail 到游戏目录）、JS 选项（`js.ecmascript-version=latest`、`js.commonjs-require=true` 等）。
- **`NekoSharedHostAccess`**：构建 `HostAccess`，把所有 `JSTypeAdapter` 注册为 `targetTypeMapping`。
- **`ClassFilter`**：`Predicate<String>`，高危 Java 类黑名单（Runtime/Process/ClassLoader/反射/io/nio/net/polyglot 本身等）。

### 2. 编译前端与模块系统（`core/compiler/`、`core/module/`）

- **TypeScript**：`NekoTypeScriptCompiler` 是手写的 lexer 基础**可擦除 TS**前端，擦除类型注解、`type`/`interface`、泛型、`as`/`satisfies`，把 `enum`/`namespace` 转 IIFE。
- **JSX**：`NekoJsxCompiler` 把 JSX lowering 到 `__nekoJsxFactory` 调用（classic runtime）。
- **ESM**：`core/module/esm/` 是完整的 native ESM 实现，自带 lexer/parser/linker，状态机 NEW→LINKING→LINKED→EVALUATING→EVALUATED，支持热重载（`ModuleReloadCoordinator`）。
- **Node shim**：`core/node/` 提供 fs/path/buffer/process/timers/util/events/assert/os/test 的 Java+JS 实现。
- **`java:` 模块**：`NekoModuleResolver` 把 `java:package/path` 解析为合成 ESM 模块。

### 3. 插件与扩展点（`api/`、`core/plugin/`）

NekoJS 的扩展模型是**插件即 API**：

- **`NekoJSPlugin`**（`api/NekoJSPlugin.java`）：~20 个 default 钩子方法的接口。内置功能（`NekoJSCorePlugin`）和第三方插件实现同一接口。
- **`@RegisterNekoJSPlugin`**：标记插件类，平台 loader（`NeoForgePluginLoader`/`ForgePluginLoader`）扫描发现。
- **`NekoJSBasePluginManager`**：发现、过滤（`clientOnly`/`requiredMods`）、实例化、按 priority 排序。
- **`NekoPluginBootstrap`**：编排所有扩展点（`nekojs:bindings`、`nekojs:adapters`、`nekojs:events`、`nekojs:recipe_schemas` 等），收集后冻结注册表，发布 `NekoPluginRuntime`。
- **`NekoPluginExtensionPoint`/`NekoPluginExtensionProvider`**：开放式 SPI，插件可注册自定义扩展点。

详见 [插件开发](插件开发)。

## 平台抽象（SPI）

不是 Java ServiceLoader，而是**手动单例 init**：

| SPI | 位置 | 作用 |
|---|---|---|
| `IPlatform` + `Platform` 门面 | `common/.../platform/` | 环境信息（`isClient`/`getMcVersion`/`capabilities`）。平台启动时 `Platform.init(new NeoForgePlatform())` 一次。 |
| `NekoIdCompat` | `common/.../platform/` | `NekoId` ↔ 平台原生 ID（`Identifier` / `ResourceLocation`）转换。 |
| `NekoCatalogPlatformProvider` | `common/.../api/catalog/` | 给 probe 喂注册表字面量、recipe namespace handler、host extension 声明。每平台实现一个。 |
| `@RegisterNekoJSPlugin` 发现 | 平台 loader | 扫描注解类交给 common 的 plugin manager。 |

平台能力由 `PlatformCapability` 枚举表达（22 个特性标志：`RECIPE_HOT_RELOAD`、`TAGS`、`NETWORK_CUSTOM_CHANNEL`、`CLIENT_*` 等），common 代码据此 feature-gate。

## 字节码注入机制

不同平台用不同机制给原版类加行为：

| 平台 | 机制 |
|---|---|
| **NeoForge 26.x** | `interfaceInjectionData`（`nekojs.interface_injection.json`）+ 空 `Mixin implements *Extension`（最干净） |
| **NeoForge 1.21.1** | 仅 Mixin `implements`（interface injection 禁用） |
| **Cleanroom 1.12.2** | Mixin（运行时配方移除、配方管理器、JEI accessor）**+** launchwrapper `IClassTransformer` coremod（`@StaticInjector` 静态方法注入，因为 Mixin 不能安全注入 public static 方法） |

## 事件系统（`api/event/` + `eventbus/`）

- **`EventGroup`**：命名的事件总线集合，`group.server("name", EventClass)` 等工厂方法。
- **`EventBus`/`CancellableEventBus`/`DispatchEventBus`**：总线接口，dispatch 版支持按 key 分发（如按方块/物品 id）。
- **`EventBusJS`**：GraalJS 面向的 `ProxyExecutable`，让脚本能 `ServerEvents.recipes(cb)` 这样调。
- **`EventBusForgeBridge`**：把平台事件（NeoForge `IEventBus` / Forge `EVENT_BUS`）桥接进中立总线。
- **`api/event/` 持接口，`eventbus/` 持实现**（`EventBusImpl`/`CancellableEventBusImpl`/`dispatch/*`）。

## 配方系统（`api/recipe/` + 平台 `wrapper/`、`bindings/recipe/`）

- **`RecipeTypeDefinition`**：schema 定义（namespace/type/fields/constructors/unique）。
- **`RecipeTypeDefinitionStorage`**：三层优先级合并（auto-discovered < plugin override < data-driven JSON）。
- **`RecipeSchemaAutoDiscovery` + 平台 `MinecraftRecipeSchemaScanner`**：反射 MC `RecipeSerializer.codec()` 自动生成 schema（NekoJS 独有，KubeJS 没有）。
- **`RecipeNamespaceProxy`/`SchemaRecipeBuilder`/`FallbackNamespaceProxy`**：脚本侧 `event.recipes.<ns>.<type>(...)` 的代理层。解析顺序：handler 方法 → schema → 原始 JSON 兜底。
- **平台 `RecipeManagerMixin`**：缓存原始配方 JSON、应用脚本配方。1.12.2 直接 `ForgeRegistries.RECIPES.register`，现代版本走数据包 JSON。

## Probe（`probe/`）

`ProbeOrchestrator` 反射 Java 类生成 `.d.ts`，原子 staging-dir 交换。详见 [Probe 类型生成](Probe-类型生成)。

## 设计原则（来自 ROADMAP）

1. **JSON 优先**：配方、数据尽量用 JSON，脚本只写逻辑。
2. **绑定即原版类**：能直接暴露 MC 类就暴露，少造 wrapper。
3. **避免 Graal `Value` 泄漏**：API 边界尽量用具体 Java 类型，`Value` 只在 interop 层用。
4. **common 无 MC 依赖**：所有 MC 相关代码在平台模块。
5. **插件即 API**：内置功能与第三方插件走同一扩展面。
