# 注解体系

> NekoJS 的注解分两类：**(A) 控制 JS 可见性与命名**（运行时由 GraalJS 的 `MemberRemapper` + 反射层消费）；**(B) 控制文档与 probe 输出**（由 `TypeDocsRegister` + probe 消费）。本页是完整参考。
> 所有注解的 Javadoc 一律英文，本页用中文解释。

## 注解总览

| 注解 | 目标 | 类别 | 作用 |
|---|---|---|---|
| `@RegisterNekoJSPlugin` | TYPE | 元 | 标记插件类 |
| `@Remap` | TYPE/METHOD/FIELD/PARAM | A | 把 Java 名重命名为 JS 名 |
| `@RemapByPrefix` | TYPE | A | 按前缀批量重命名 |
| `@HideFromJS` | TYPE/METHOD/FIELD/PARAM | A | 对 JS 不可见 |
| `@StaticInjector` | METHOD | A | coremod 静态注入标记 |
| `@CalledByDynamicCode` | METHOD/PARAM | A | 标记被生成的 JS 调用（IDE 不报 unused） |
| `@Doc` | TYPE/METHOD/FIELD/PARAM | B | 主描述（→ JSDoc body） |
| `@Param` | PARAM | B | 参数名 + 描述 |
| `@Return` | METHOD | B | 返回值描述 |
| `@Example` | TYPE/METHOD | B | 用例（→ `@example`） |
| `@Overload` | METHOD | B | 额外 TS 签名 |
| `@TypeOverride` | METHOD/FIELD | B | 强制 probe 用指定类型 |
| `@Since` | TYPE/METHOD/FIELD/PARAM | B | 冻结版本（SemVer） |
| `@DeprecatedNekojs` | TYPE/METHOD/FIELD/PARAM | B | 弃用元数据 |

所有注解都是 `@Retention(RUNTIME)` + `@Documented`。包：`com.tkisor.nekojs.api.annotation`（元注解 `@RegisterNekoJSPlugin`）和 `com.tkisor.nekojs.api.annotation`（其余）。

## A 类：JS 可见性与命名

这些注解由 `JavaMemberIndex` + `MemberVisibilityQuery` + `NekoJSMemberRemapper` 在运行时消费，控制脚本作者实际看到什么。

### `@Remap("jsName")`

把 Java 成员/类型重命名成 JS 可见的名字。

```java
public class FooJS {
    @Remap("addItem")            // 脚本里调 foo.addItem(...) 而不是 foo.addItemInternal(...)
    public void addItemInternal(ItemStack stack) { ... }
}
```

> 用途：Java 命名规范（camelCase 方法、下划线常量）与 JS 习惯不一致时，或想让 API 更友好。运行时 GraalJS 的 `MemberRemapper` 会把 `addItem` 映射回 `addItemInternal`。

### `@RemapByPrefix`

按前缀批量重命名一个类里的成员。常用于把 `getXXX`/`setXXX` 转成属性式。

```java
@RemapByPrefix({
    @RemapByPrefix.Entry(prefix = "get", strip = true),   // getX → x
    @RemapByPrefix.Entry(prefix = "is", strip = true)     // isX → x
})
public class FooJS { ... }
```

### `@HideFromJS`

让成员对 JS 完全不可见（既不能调，probe 也不生成）。

```java
public class FooJS {
    @HideFromJS
    public void internalHelper() { ... }   // 脚本看不到这个方法
}
```

也可标在类上（整个类对 JS 不可见）。

### `@StaticInjector("target.class.Name")`

**Cleanroom 1.12.2 coremod 专用**。标记一个 `public static` 方法，由 `NekoClassTransformer`（launchwrapper `IClassTransformer`）注入到目标 MC 类。

```java
public class ItemStaticExtensions {
    @StaticInjector("net.minecraft.item.Item")
    public static ItemStack of(String id) { ... }   // 注入到 net.minecraft.item.Item.of
}
```

> 为什么用 coremod 而不是 Mixin：Mixin 不能安全注入 public static 方法（会触发 bootstrap NPE）。

### `@CalledByDynamicCode`

标记「会被生成的 JS 代码调用」的方法/参数。让 IDE/静态分析不误报为 unused。常用于 `@CalledByDynamicCode` 标记 `NekoScriptModuleLoaderHost` 等被 `internal/script-loader.js` 调用的方法。

## B 类：文档与 probe 输出

这些注解由 `AnnotatedTypeDocsCollector` 在 bootstrap 时反射，转成 `TypeDocCatalogEntry` 灌进 `TypeDocsRegister`，probe 读取后生成进 `.d.ts`。

> **注解是 `TypeDocsRegister` 的镜像**——你也可以直接用 `registerTypeDocs` 编程式注册（用于第三方/动态场景）。单一真相源是 `TypeDocsRegister`。

### `@Doc("...")`

主描述文本，多行支持。probe 生成 JSDoc body。

```java
@Doc("物品助手。of/empty 走助手函数，其余委托 MC Item 类。")
public class ItemJS {
    @Doc("从 id 创建物品栈；支持 \"1x minecraft:stone\" 数量语法。")
    public ItemStack of(String id) { ... }
}
```

### `@Param(name = "x", desc = "...")`

参数名 + 描述。**修配方参数名退化问题**：没编译 `-parameters` 时，probe 会把参数名显示成类型名（`remove(String: string)`），`@Param` 强制指定真名。

```java
public class MinecraftRecipeHandler {
    public void crafting_shaped(
        @Param(name = "result", desc = "产物") ItemStack result,
        @Param(name = "pattern", desc = "有序图案") String[] pattern,
        @Param(name = "keys", desc = "字符到配料的映射") Map<Character, Ingredient> keys
    ) { ... }
}
```

### `@Return("...")`

返回值描述。生成 JSDoc `@returns`。

```java
@Return("新创建的物品栈")
public ItemStack of(String id) { ... }
```

### `@Example("...")`

用例。可重复（多个 `@Example`）。生成 JSDoc `@example` 块。

```java
@Example("Item.of('minecraft:stone')")
@Example("Item.of('1x minecraft:stone')")
public ItemStack of(String id) { ... }
```

### `@Overload(paramTypes = {...}, paramNames = {...})`

声明额外的 TS 签名。Java 反射只能看到一个 erased 签名，但 NekoJS 绑定常接受多种输入（通过 `JSTypeAdapter`）。`@Overload` 让 probe emit 准确的 TS 重载。

```java
@Overload(paramTypes = { String.class }, paramNames = { "id" })
@Overload(paramTypes = { String.class, int.class }, paramNames = { "id", "count" })
@Overload(paramTypes = { ItemStack.class }, paramNames = { "stack" })
public ItemStack of(Object value) { ... }   // Java 端是 Object，靠 adapter 分派
```

probe 会生成 4 条签名（1 反射 + 3 重载）。

### `@TypeOverride("fully.qualified.TypeName")`

强制 probe 用指定类型，覆盖反射推导。**取代旧版硬编码的 `overrideGetter`**。

```java
public class RecipeEventJS {
    @TypeOverride("com.tkisor.nekojs.wrapper.event.server.DocumentedRecipes")
    @Doc("配方命名空间代理；event.recipes.<ns>.<type>(...)")
    public Object getRecipes() { ... }   // Java 返回 Object，但 JS 实际看到 DocumentedRecipes
}
```

### `@Since("1.1.0")`

记录该符号何时被冻结（SemVer）。probe 生成 JSDoc `@since`。属于 [API 冻结线](#since-与-deprecatednekojs-api-生命周期)。

```java
@Since("1.1.0")
public interface NekoJSPlugin { ... }
```

### `@DeprecatedNekojs(since = "...", replacement = "...")`

弃用元数据。probe 生成 JSDoc `@deprecated`。配合 `java.lang.Deprecated` 使用（后者驱动编译器告警）。

```java
@Deprecated
@DeprecatedNekojs(since = "1.2.0", replacement = "NewItem")
public class OldItemJS { ... }
```

## @Since 与 @DeprecatedNekojs —— API 生命周期

NekoJS 采用 **SemVer + 弃用期** 策略：

1. 每个公开符号在冻结时标 `@Since("<version>")`。
2. 弃用时标 `@DeprecatedNekojs(since, replacement)` + `@Deprecated`，probe emit `@deprecated`。
3. 旧符号保留至少一个 MINOR 周期，下个 MAJOR 才移除。

插件作者写**公开 API** 时也应遵循：
- 新公开绑定的方法标 `@Doc` + `@Since`（你的插件版本）。
- 弃用旧方法时用 `@DeprecatedNekojs` + `@Deprecated`，保留兼容期。

## 最佳实践

1. **公开绑定类的方法都要 `@Doc`**：让 probe 生成的 `.d.ts` 有文档，DX 大幅提升。
2. **方法参数标 `@Param`**：特别是 handler 方法、参数名重要的 builder 方法。
3. **JS 与 Java 命名差异处用 `@Remap`**：别让脚本作者看到 `addItemInternal` 这种内部名。
4. **内部辅助方法用 `@HideFromJS`**：避免污染脚本 API 面。
5. **多输入形态用 `@Overload`**：配合 `JSTypeAdapter`，让 TS 签名准确。
6. **动态返回类型用 `@TypeOverride`**：返回 `Object` 但实际是某 wrapper 的方法。

## 与 probe 的关系（重要）

probe 当前**部分接入**了注解体系：
- ✅ `@Remap`/`@HideFromJS` 由运行时 `MemberRemapper`/`MemberVisibilityQuery` 消费（脚本运行时生效）。
- 🚧 `@Doc`/`@Param`/`@Overload`/`@TypeOverride` 正在接入 `ClassDeclGenerator`（probe 重构 Phase B）。

接入完成后，probe 会全面走 `MemberVisibilityQuery`（让 `.d.ts` 的名字/可见性与运行时一致）+ `TypeDocsRegister`（生成 JSDoc）。
