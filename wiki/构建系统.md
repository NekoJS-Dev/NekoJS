# 构建系统

> 本页讲 NekoJS 自身的构建：怎么编译各平台、模块关系、Gradle 结构、CI。**插件作者不需要读本页**（除非好奇）；贡献代码 / 发版需要。

## 模块图

```text
                      settings.gradle 引入：
                      ┌─────────────────────────────────────────────┐
                      │ :common-api                                  │
                      │ :common-api-processor                        │
                      │ :common                                      │
                      │ :platforms:neoforge-26.1                     │
                      │ :platforms:neoforge-26.2                     │
                      │ :platforms:neoforge-1.21.1                   │
                      │ :platforms:cleanroom-1.12.2                  │
                      └─────────────────────────────────────────────┘
                      （neoforge-shared / neoforge-26-shared 不被引入 —— 纯源码目录）

    ┌──────────────────────────┐
    │          :common          │   java-library，Java 21
    │  无 MC/NeoForge 依赖      │   以 implementation 依赖（编译产物）提
    │  357 Java 文件            │   供给每个平台；cleanroom 发布 jar 另
    └─────────────┬─────────────┘   外并入其 sourceSets.main.output
                  │ api project(':common-api')
                  │
        ┌─────────┼───────────────────────────┐
        ▼         ▼                           ▼
  ┌──────────┐ ┌──────────┐            ┌────────────────┐
  │ neoforge │ │ neoforge │            │ cleanroom      │
  │  -26.1   │ │  -26.2   │            │  -1.12.2       │
  │ J25      │ │ J25      │            │ J25, Forge,    │
  │ moddev   │ │ moddev   │            │ unimined,      │
  └────┬─────┘ └────┬─────┘            │ shadow, blossom │
       │            │                  └────────────────┘
       └─────┬──────┘
             │  拉共享源码：
             ▼
    ┌─────────────────────────────────────┐
    │ platforms/                          │  *** 不是 Gradle 模块 ***
    │   neoforge-shared/                  │  无 build.gradle，不在 settings.gradle
    │     src/main/java                   │  1.21.1 + 26.1 + 26.2 主源码共享
    │   neoforge-26-shared/               │  主源码仅 26.1/26.2 吸收；
    │     src/main/{java,resources,       │  src/test/java 由 1.21.1 + 26.1 + 26.2
    │              templates}             │  三平台共用（按双版本兼容 API 编写）
    │     src/test/java                   │
    └─────────────────────────────────────┘

  ┌──────────────────┐
  │ neoforge-1.21.1  │  J21, moddev。implementation 依赖 :common。
  │                  │  主源码不用 26-shared（API 漂移过大），
  │                  │  但复用 ../neoforge-26-shared/src/test/java。
  └──────────────────┘
```

**关键点**：
- 每个平台都 `implementation project(':common')` 消费其**编译产物**；没有任何平台再 `srcDir` 拉 `:common` 源码（旧「双重装配」已消除）。cleanroom 的发布 jar 会把 `:common` / `:common-api` 的 `sourceSets.main.output` 直接并入。
- `neoforge-shared` 与 `neoforge-26-shared` 都是**纯目录**，无 build.gradle：前者主源码由 1.21.1/26.1/26.2 吸收，后者主源码由 26.1/26.2 吸收、测试源码由三个 NeoForge 平台共用。
- 平台之间无相互 Gradle 依赖。

## 各模块构建配置

### `:common`

| 项 | 值 |
|---|---|
| 插件 | `java-library`, `idea` |
| Java 工具链 | 21 |
| 关键依赖 | GraalJS `curse.maven:graal-1504336:8456810`（api 依赖，标签 25.1.3.6）
| 产物 | `nekojs-1.1.0-preview2.jar`（无 shadow；各平台以 `implementation` 依赖消费编译产物，不再 srcDir 拉源码） |

`common/build.gradle` 只声明 `java-library`，无 MC 依赖。**这是多平台共享的前提**。边界由两个 Gradle 门禁任务强制：
- `:common:checkCommonIsolation`：拒绝 `common/src/main` 中的 `net.minecraft`/`net.minecraftforge`/`net.neoforged` import（Graal 允许，common 有意拥有引擎），接入 `check`。
- `:common-api:checkApiBoundaries`：拒绝 `common-api` 中的 MC/Forge/NeoForge/Graal/非 api 包 nekojs import。

### `:platforms:neoforge-26.1` / `:neoforge-26.2`

| 项 | 值 |
|---|---|
| 插件 | `java-library`, `maven-publish`, `idea`, `net.neoforged.moddev 2.0.140`, `me.shedaniel.unified-publishing 0.1.13`（经版本目录 `libs.plugins.unified.publishing`） |
| Java 工具链 | 25 |
| MC/NeoForge | 26.1: MC 26.1.2 / NeoForge 26.1.2.36-beta；26.2: MC 26.2.0 / NeoForge 26.2.0.7-beta |

| 依赖 | `project(':common')` + GraalJS + JEI（`jei-238222:7920926` for 26.1，`:8300448` for 26.2） |
| 产物 | `nekojs-neoforge-<mcversion>-<modversion>.jar`（26.1 ~566 类，26.2 ~564 类） |

### `:platforms:neoforge-1.21.1`

| 项 | 值 |
|---|---|
| 同 26.x 插件集 | — |
| Java | 21 |
| MC/NeoForge | MC 1.21.1 / NeoForge 21.1.227 |
| sourceSets | `../neoforge-shared/src/main/java` + 本地（主源码**不用 26-shared**）；test 复用 `../neoforge-26-shared/src/test/java`（:common 走 implementation 依赖） |
| interface injection | 禁用（build.gradle 注释掉） |
| 依赖 | `project(':common')` + GraalJS + JEI `jei-238222:7420587` |

**为何自包含**：1.21.1 与 26.x 的 API 漂移（92 个同路径文件不同）较大，共享源码带来的收益不足以抵消条件编译复杂度。

### `:platforms:cleanroom-1.12.2`

Forge 1.12.2 **纯 Mixin + AT mod**（非 coremod）。

| 项 | 值 |
|---|---|
| 插件 | `java`, `java-library`, `maven-publish`, `idea`, `com.gradleup.shadow 9.4.1`, `xyz.wagyourtail.unimined 1.4.23-kappa`, `net.kyori.blossom 2.2.0`（均经版本目录） |
| Java | 25 |
| MC/Loader | MC 1.12.2 / Cleanroom（Forge）0.5.14-alpha / MCP mappings `stable-39-1.12` |
| sourceSets | 本地（:common / :common-api 走 implementation 依赖，发布 jar 直接并入两者的 `sourceSets.main.output`） |
| 依赖 | Cleanroom sponge-mixin `0.20.13`；HEI `had-enough-items-557549:8081514`；Immersive Engineering（runtime）；GraalJS via `contain`（**捆绑进 jar**）；night-config（contain） |
| 产物 | remapped jar，**含捆绑的 GraalJS + night-config**（94 本地 Java 文件） |
| jar manifest | `ModType=CRL`, `MixinConfigs=nekojs.default.mixin.json,nekojs.mod.mixin.json`, `FMLAT=nekojs_at.cfg`, `ContainedDeps=...`, `NonModDeps=true` |

`jar` 任务把所有 `contain` 配置依赖（GraalJS + night-config）直接 `zipTree` 提取进 jar；未 remap 的 jar 标 `dev` 分类，由 UniMineD 的 `remapJar` finalize。`processResources` 把 `*_at.cfg` 重定位到 `META-INF/`。Shadow 默认禁用（`enable_shadow=false`）。

**不用 `neoforge-common.gradle`**（是 Forge 不是 NeoForge）。

## 共享 Gradle 脚本

### `gradle/neoforge-common.gradle`

3 个 NeoForge 模块（26.1/26.2/1.21.1）共享的 **apply 脚本**（非 buildSrc 约定插件）。集中**逐字节相同**的配置：

- `base.archivesName`、`repositories`（mavenCentral + cursemaven）
- `tasks.withType(Jar)` 的命名
- `publishing`（本地 maven 发布）
- `unifiedPublishing`（CurseForge/Modrinth，门控于环境变量）
- `idea` 模块下载源
- dev-mod 源码集门禁：`register_shared_dev_mod_source_sets` 开关 + `verifyDevModSourceSets` 任务（校验 ModDev 模型的 mod source set 包含本地/common/common-api 编译产物，接入 `check`；26.1/26.2 启用，1.21.1/cleanroom 未启用）

**不集中**（各平台本地，因随 MC 版本变）：`runs`、`sourceSets`、`accessTransformers`、`generateModMetadata`、`dependencies`。

> 为何用 apply 脚本而非 buildSrc 约定插件：第三方插件（moddev/unified-publishing）的 plugin-marker 坐标随版本漂移，在 buildSrc 硬编码会增加维护负担。apply 脚本让各平台自声明插件版本，只集中相同配置块。

### `gradle/libs.versions.toml`（版本目录）

所有模块通过 `libs.*` 访问器引用共享依赖/插件版本，集中消除散落硬编码：

- **集中**：lombok `1.18.44`、jetbrains-annotations `24.1.0`、jspecify `1.0.0`、night-config `3.8.3`、gson、log4j、icu4j、Graal `curse.maven:graal-1504336:8456810`、junit-bom `6.0.0`、插件（moddev `2.0.140`、unified-publishing `0.1.13`、shadow、unimined、blossom）。
- **刻意留本地**（有分歧原因）：slf4j（cleanroom 锁 `1.7.36`，MC 1.12.2 内置 slf4j 1.7）、junit-jupiter（common/common-api 用 BOM 6.0.0，平台用 5.14.3 迁移期）、curse.maven 坐标（JEI 每平台不同文件 id）。
- foojay-resolver 插件在 settings.gradle 硬编码（settings 的 `plugins {}` 块在版本目录绑定前求值，无法用 `alias`）。

## 共享源码集机制（neoforge-shared + neoforge-26-shared）

最重要的源码共享机制。NeoForge 三平台通过**源码集组合**（非模块依赖）避免重复：

```groovy
// platforms/neoforge-26.1/build.gradle（26.2 同理）
sourceSets {
    main {
        java {
            srcDir '../neoforge-shared/src/main/java'       // 1.21.1 + 26.x 主源码共享
            srcDir '../neoforge-26-shared/src/main/java'    // 26.1/26.2 主源码共享
        }
        resources {
            srcDir '../neoforge-26-shared/src/main/resources' // 共享 AT + interface-inj
        }
    }
    test.java.srcDir '../neoforge-26-shared/src/test/java'  // 三个 NeoForge 平台共用测试
}

// platforms/neoforge-1.21.1/build.gradle：main 只吸收 neoforge-shared，
// 不吸收 26-shared 主源码（API 漂移过大）；test 同样从 26-shared 拉测试。
```

共享配置文件也从 26-shared 引用：
- `accessTransformers = project.files('../neoforge-26-shared/.../accesstransformer.cfg')`
- `interfaceInjectionData.from('../neoforge-26-shared/.../nekojs.interface_injection.json')`
- `generateModMetadata.from('../neoforge-26-shared/src/main/templates')`

**为何如此**：26.1/26.2 共享 ~95% 相同代码，但仅差少量 Mojang 重命名。factoring 进 26-shared 把每平台本地树降到 4-6 文件；版本无关的子集进一步放进 neoforge-shared，1.21.1 也吸收其主源码。26-shared 的测试按双版本兼容 API 编写，因此 1.21.1 无需 fork 也能复用同一套测试。

## CI（`.github/workflows/ci-build.yml`）

单一工作流「NekoJS CI Build」，3 个 job：

1. **`analyze`**：解析提交标题；`^update\s+(\S+)$` 检测为 release。
2. **`build`**（needs analyze）：JDK 25 + `gradle/actions/setup-gradle@v4`。执行顺序：
   - `:common-api:check :common:test`（含 `checkApiBoundaries` 边界门禁）
   - `nbtSmokeTest`（portable NBT smoke 聚合，见上）
   - `npm run test:probe-types`（Probe 声明类型检查）
   - **动态发现平台模块**（扫描含 `build.gradle` 的 `platforms/*`，所以无 build.gradle 的 `neoforge-shared` / `neoforge-26-shared` 自动跳过）。先跑所有 `:platforms:<name>:compileJava`，再 `:build`，收集 jar。
3. **`release`**（needs analyze + build，仅 push 且 is_release）：生成 changelog，创建 GitHub release，附加 jar。

## 怎么编译

### 编译单个平台

```bash
./gradlew :platforms:neoforge-26.1:build
./gradlew :platforms:cleanroom-1.12.2:build
```

产物在 `platforms/<name>/build/libs/`。

### 编译全部平台

```bash
./gradlew build
```

### 只跑 common 测试

```bash
./gradlew :common:test
```

> common 测试覆盖 `api/data`、contract、managed facade、compiler、plugin、probe、platform 与 filesystem 等模块，不依赖 Minecraft runtime。

### Portable NBT smoke test

```bash
./gradlew nbtSmokeTest
```

该聚合任务只运行带 `nbt-smoke` tag 的测试，覆盖 common 的受限 Graal managed API 与 sandbox filesystem，以及 NeoForge 1.21.1、NeoForge 26.1、NeoForge 26.2、Cleanroom 1.12.2 的真实 Minecraft NBT codec。平台测试会在临时 game directory 中通过 production `DefaultNbtFacade` 写入压缩 NBT，重新创建 facade 模拟重启后读取，并验证 missing file、path traversal、损坏文件、root compound、深度、大小和 unsupported native tag 错误。

该任务不启动完整 Minecraft dedicated server，不需要图形环境、world 或 EULA，适合 CI。CI 还会运行全部 common/platform tests 与 `verifyRuntimeArtifact`，后者确认最终 jar 包含 portable contract、filesystem store 和对应平台 native codec。

### 在 IDE 里跑

各平台 `build.gradle` 都有 `idea` 插件 + `neoForge.ideSyncTask` / UniMineD 的 IDE 同步。导入根 `build.gradle` 即可。

## 发版

由 CI 自动：提交标题匹配 `^update\s+(\S+)$` 触发 release job，用 `unified-publishing` 上传 CurseForge/Modrinth（门控于 `CURSEFORGE_KEY`/`MODRINTH_TOKEN` 环境变量）。详见 `gradle/neoforge-common.gradle` 的 `unifiedPublishing` 块。

## 已知技术债（计划修复）

- srcDir+impl 双重装配已消除：各平台现在只以 `implementation` 消费 `:common` 编译产物，没有平台再 srcDir 拉 common 源码。
- `:common-api` / `:common` 拆分已完成；注解处理器（`:common-api-processor`）只依赖 `:common-api`。但插件目前编译依赖平台 fat jar（内含 `:common` 全部类），插件入口类型仍在 `:common` 的 `com.tkisor.nekojs.api.*` 包——可独立依赖的稳定 SPI 尚未形成。
- cleanroom 曾为 launchwrapper coremod（`@StaticInjector` 注入），现已改为纯 Mixin+AT。
- legacy binding 同步仍有未完成项；portable `JsonIO` 与 binary `NBT` 已覆盖 NeoForge 和 Cleanroom。
