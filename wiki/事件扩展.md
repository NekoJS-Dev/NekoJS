# 事件扩展

> 本页讲两件事：(1) 插件如何注册**自定义事件组**（让脚本像用 `ServerEvents` 一样用你的事件）；(2) 用户如何在**启动脚本**里用 `ScriptEvents` 把原版事件桥接成新事件组。

## 概念回顾

NekoJS 的事件系统（见 [项目架构 - 事件系统](项目架构#事件系统apievent--eventbus)）：

- **`EventGroup`**：命名的总线集合。`group.server("name", EventClass)` 工厂方法声明一个事件。
- **`EventBus`/`CancellableEventBus`/`DispatchEventBus`**：三种总线。dispatch 版按 key 分发（如按物品/方块 id）。
- **`EventBusJS`**：GraalJS 面向的 `ProxyExecutable`，让脚本 `事件组.事件名(cb)` 这样调。
- **`EventBusForgeBridge`**：把平台事件桥接进中立总线。

事件组在 `bindings/event/` 下以 interface 形式声明，例如：

```java
public interface ServerEvents {
    EventGroup GROUP = EventGroup.of("ServerEvents");

    EventBusJS<RecipeEventJS, Void> RECIPES = GROUP.server("recipes", RecipeEventJS.class);
    EventBusJS<TagEventJS, Identifier> TAGS =
        GROUP.server("tags", TagEventJS.class, TAG_REGISTRY_KEY);   // dispatch 总线
}
```

## 插件注册自定义事件组

### 步骤 1：定义事件对象类

你的事件对象就是脚本回调里收到的 `event`。可以是个普通 Java 类或 record：

```java
package com.example.myaddon;

import net.minecraft.server.level.ServerPlayer;

public class PlayerGreetEvent {
    private final ServerPlayer player;
    private final String greeting;
    public PlayerGreetEvent(ServerPlayer player, String greeting) {
        this.player = player; this.greeting = greeting;
    }
    public ServerPlayer getPlayer() { return player; }
    public String getGreeting() { return greeting; }
}
```

> 要给事件对象加 JSDoc，直接在事件类的方法/参数上标注 `@Doc`/`@Param`/`@Return`（probe 生成进 JSDoc），或用编程式 `registerTypeDocs`（`TypeDocsRegister.register(...)`，见 [插件开发](插件开发)）。

### 步骤 2：声明事件组

```java
package com.example.myaddon;

import com.tkisor.nekojs.api.event.EventGroup;
import com.tkisor.nekojs.api.event.EventBusJS;
import net.minecraft.resources.Identifier;

public interface MyEvents {
    EventGroup GROUP = EventGroup.of("MyEvents");

    // 普通服务端事件
    EventBusJS<PlayerGreetEvent, Void> PLAYER_GREET =
        GROUP.server("playerGreet", PlayerGreetEvent.class);

    // dispatch 事件（按 Identifier 分发）
    EventBusJS<MyCustomEvent, Identifier> CUSTOM =
        GROUP.server("custom", MyCustomEvent.class, MY_DISPATCH_KEY);
}
```

`EventGroup` 的工厂方法：

| 方法 | 总线类型 | 用途 |
|---|---|---|
| `GROUP.server(name, eventClass)` | `EventBus` | 一律 `EventBusJS.of(type)`；可取消性由事件类自动检测（`EventBusJS.eventCancellability(type)`），不取决于工厂变体或回调写法 |
| `GROUP.server(name, eventClass, dispatchKey)` | `DispatchEventBus` | 按 key 分发 |
| `GROUP.client(...)` / `GROUP.startup(...)` | 同上 | 客户端/启动侧别 |

### 步骤 3：在插件里注册事件组

```java
@Override
public void registerEvents(EventGroupRegistry registry) {
    registry.register(MyEvents.GROUP);
}
```

### 步骤 4：派发事件

在合适的时机（比如你的 mod 监听原版事件时）post 你的事件：

```java
import com.tkisor.nekojs.api.event.EventBusJS;

// 普通事件
MyEvents.PLAYER_GREET.post(new PlayerGreetEvent(player, "你好"));

// dispatch 事件（带 key）
MyEvents.CUSTOM.post(someIdentifier, new MyCustomEvent(...));

// 可取消事件（返回 true 表示被取消）
boolean cancelled = MyEvents.PLAYER_GREET.post(new PlayerGreetEvent(player, "你好"));
if (cancelled) { /* 脚本取消了 */ }
```

> `post(...)` 返回 boolean（是否被取消）。对于不可取消的总线总是返回 false。

### 脚本侧用法

注册后，脚本就能像内置事件一样用：

```javascript
MyEvents.playerGreet(event => {
  console.info(`${event.getPlayer().getName().getString()} 被问候：${event.getGreeting()}`)
})

MyEvents.custom('mymod:some_key', event => {
  // dispatch 事件，第一个参数是 key
})
```

## ScriptEvents —— 让脚本自己注册事件

NekoJS 还提供一个**面向脚本作者**的机制：在 `startup_scripts/` 里把任意原版事件桥接成一个新的事件组，之后在 `server_scripts`/`client_scripts` 里就能像内置事件一样监听。

### 字符串形式

```javascript
// startup_scripts/register_events.js
ScriptEvents.server(event => event.register(
  'CustomServerEvents',                                   // 事件组名（会成为全局绑定名）
  'playerTick',                                            // 事件名
  'net.neoforged.neoforge.event.tick.PlayerTickEvent.Post' // 原版事件类 FQN
))

ScriptEvents.client(event => event.register(
  'CustomClientEvents',
  'screenOpening',
  'net.neoforged.neoforge.client.event.ScreenEvent$Opening'
))
```

### 对象形式（带 priority/receiveCancelled）

```javascript
ScriptEvents.server(event => event.register({
  group: 'CustomServerEvents',
  name: 'rightClickBlock',
  event: 'net.neoforged.neoforge.event.entity.player.PlayerInteractEvent$RightClickBlock',
  priority: 'normal',           // 'lowest'/'low'/'normal'/'high'/'highest'/'first'
  receiveCancelled: false
}))
```

### 然后在对应脚本类型里监听

```javascript
// server_scripts/use_custom.js
CustomServerEvents.playerTick(event => {
  console.info(`玩家 tick：${event.getEntity().getName().getString()}`)
})

CustomServerEvents.rightClickBlock(event => {
  console.info(`右键了方块：${event.getPos()}`)
})
```

```javascript
// client_scripts/use_custom_client.js
CustomClientEvents.screenOpening(event => {
  console.info(`打开了 Screen：${event.getScreen()}`)
})
```

### 规则

- `group` 和 `name` 必须是合法 JS 标识符。
- `event` 是原版事件类的 FQN，嵌套类用 `$`（如 `...Event$Post`）。
- `ScriptEvents.server(...)` 注册的事件在 `server_scripts` 可用；`.client(...)` 注册的在 `client_scripts` 可用。
- **probe 覆盖**：动态注册的事件组/事件会进入事件目录与 probe 类型生成（`.d.ts` / `.pyi`）——自定义事件组渲染为普通事件组，事件 payload 按事件类的 public getter 反射生成声明，IDE 补全与内置事件一致。
- **startup reload** 会刷新事件定义；**server/client reload** 清除监听器（不重新注册定义）。
- **平台差异**：`ScriptEvents` 目前仅在 NeoForge（26.x / 1.21.1）可用；Cleanroom 1.12.2 上注册会抛 `UnsupportedOperationException`（提示改用类型化事件绑定或 `NativeEvents.onEvent(...)`）。

## EventBusForgeBridge

如果你的事件组要桥接**平台原生事件**（NeoForge `IEventBus` / Forge `EVENT_BUS`），用 `EventBusForgeBridge`：

```java
EventBusForgeBridge.create(NeoForge.EVENT_BUS)
    .bind(MyEvents.PLAYER_GREET)        // 把每个事件绑到一个原生事件
    .bind(MyEvents.CUSTOM);
```

`bind(...)` 会订阅原生事件，转发进中立总线，并把取消传播回原版 `ICancellableEvent`。详见内置事件组（如 `ServerEvents.java` 末尾的 `FORGE_BRIDGE`）。

## 设计要点

1. **事件对象尽量简单**：POJO 或 record；文档用编程式 `registerTypeDocs` 补充。
2. **dispatch key 要稳定**：dispatch 事件的 key 类型（`Identifier`/`String`/`Class`）一旦发布就不要改（属于 API 冻结线）。
3. **可取消事件**：如果脚本 `return true` 应该影响游戏行为（取消破坏、阻止传送等），用 `CancellableEventBus`。
4. **跨侧**：服务端事件用 `.server(...)`，客户端用 `.client(...)`，启动用 `.startup(...)`。误用会在加载时报错。
5. **无监听器短路**：构建成本高的发射点（probe 等）先用 `EventBusJS.hasListeners()` 检查，没有监听器就跳过事件对象构建。
