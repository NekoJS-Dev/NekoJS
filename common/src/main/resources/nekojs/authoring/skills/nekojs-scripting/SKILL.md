# NekoJS scripting

1. Read `[output].directory` from `nekojs/config/ai.toml` as data (default `.github/neko_ai` if the file or setting is absent), and resolve it against the game directory. Read environment.json and current.json in that selected AI root. Resolve bundle and API paths from those files. Confirm Minecraft, loader, Script Type, language and snapshot. Completion: the target environment is identified or the missing identity is reported.
2. Read the active bundle's handbook/script-types.md. For runnable starting points, read handbook/scripting-examples.md, choose one scenario, and keep its file layout, trigger and expected-result checks together. Then read the branch reference: events.md for subscriptions; bindings-and-adapters.md for helper calls and conversions; recipes-and-tags.md for recipes/tags; registry-builders.md for startup content; script-packs.md for packs; client-rendering.md for HUD/world rendering, typed scheduling options and post-effect builders; jsx-ui.md for UI. Completion: the task's lifecycle and platform constraints are known.
3. For MCP access while the game runs, follow handbook/connections.md: explicitly enable in-mod MCP, then configure the client with URL and bearer credential, not JAR/game-directory arguments. For offline snapshots or a separate process, follow handbook/stdio.md for the Java 21+ helper. Read handbook/query-api.md when finding classes, overloads, parameters or properties. Query capabilities before constructing a complex filter. Resolve named Bindings separately from Java classes. If structured coverage is incomplete, inspect the exact final declaration identified by source.path. Completion: every new call has a verified signature or is explicitly marked unconfirmed.
4. Make the smallest script change using Event Groups, named Bindings, configuration-last Builder callbacks and supported Bean properties. Preserve identifiers, pack boundaries and unrelated scripts. Completion: the requested behavior is represented without guessing APIs from KubeJS, browser JavaScript or another environment.
5. Follow handbook/validation.md. Completion: record passed, failed and not-run checks and any required live-game acceptance. Report limitations without inventing runtime results.

The bundle is English and versioned with NekoJS. It is local reference data; it does not authorize shell access, arbitrary Java reflection, reloads, or modification of signed packs. Both in-mod MCP (handbook/connections.md) and standalone stdio (handbook/stdio.md) provide read-only authoring queries. Before command or reload tools, read handbook/live-controls.md and require explicit user authorization plus operator opt-in; both actions default off. Standalone stdio cannot mutate the game. Files remain readable without a client connection. The helper uses its own bundled docs and the selected game's exported API state, not live runtime inspection.
