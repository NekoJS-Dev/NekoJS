# Stable and version API modules

Use the declarations generated by the current instance and Script Type. `stable` is an author's commitment to a portable public surface; `version` exposes the current node's API. Selecting either category does not adapt native semantics or guarantee availability in every loader, Minecraft version or Script Type.

```ts
import { ID, Native } from "nekojs/api/stable";
import { Item } from "nekojs/api/version";

const resource = ID.resource("minecraft:stone");
const nativeId = Native.ids.toNative(resource);
const restored = Native.ids.fromNative(nativeId);
```

The stable Binding module exposes `ID` and the explicit `Native` interoperability bridge; `I18n` is CLIENT-only. The version Binding module exposes the current node's `Item` helper. Third-party Binding modules use `nekojs/plugins/<owner>/api/stable` and `nekojs/plugins/<owner>/api/version`. These Binding paths are distinct from custom engine event virtual modules. Event modules have exactly two categories: official `nekojs:event/stable` and `nekojs:event/versioned`, with an optional owner suffix for plugin events such as `nekojs:event/stable/myaddon` or `nekojs:event/versioned/myaddon`. Old event routes have no aliases. The event modules have no server/player submodules. Query the current environment's signatures; Fabric and NeoForge event sets differ.

ESM named imports and CommonJS destructuring use the same frozen, Context-local namespace:

```ts
const { ID } = require("nekojs/api/stable");
const id = ID.of("stone"); // nekojs:stone, preserving the legacy default
```

Literal `require` routes are typed; an unknown string route returns `unknown`. A module-only export creates no global. Existing ordinary global Bindings remain supported. Java plugin/native Event Groups require explicit imports and have no global aliases; script-created dynamic groups remain global, while the `ScriptEvents` registrar itself is imported from `nekojs:event/versioned`; existing domain modules such as `nekojs/commands` are separate and unchanged. Importing a member unavailable in the selected environment fails instead of producing a placeholder.

## ID and native values

`ID.of` retains the historical permissive, nonblank namespace/path grammar. `ID.resource` is strict: namespace `[a-z0-9_.-]+`, path `[a-z0-9/._-]+`, default namespace `nekojs`; it does not trim, lowercase or repair input. Native ID conversion also validates this strict grammar. Invalid IDs produce `NEKO-4056`.

`Native.ids` converts in both directions using the selected node's actual native identifier class. Native bridge parameters and returns are intentionally profile-specific, not portable wrappers. This bridge does not fabricate loader objects or make arbitrary native APIs stable.

## Native entity conversion

`Native.entities` converts between a real Minecraft entity and its stable view during a synchronous script callback. `fromNative(entity)` selects the most specific supported wrapper. `toNative(view)` and the typed variants `toNativeLivingEntity(view)`, `toNativePlayer(view)` and `toNativeServerPlayer(view)` return the exact original Minecraft instance. Native types and methods depend on the active profile. Keep native access inside the callback. Invalid inputs and expired stable views are rejected with `NEKO-4067` or the ordinary API overload error.

```ts
import { Native } from "nekojs/api/stable";
import { PlayerEvents } from "nekojs:event/stable";

PlayerEvents.chat(event => {
    const player = event.player?.asServerPlayer();
    if (!player) return;
    const nativePlayer = Native.entities.toNativeServerPlayer(player);
    const stablePlayer = Native.entities.fromNative(nativePlayer).asServerPlayer();
    console.info(stablePlayer?.uuid);
});
```

## Plugin publication

In the existing binding hook, publish a public view explicitly:

```java
registry.register(Binding.of("Widget", helper, WidgetView.class), expose -> expose.stable());
```

Use `versioned()` for native-dependent helpers. The configured overload is module-only; call the legacy overload separately only when a global is also intended. The loader supplies the owning mod ID. A missing owner, duplicate export, invalid export name, empty target or repeated target fails with `NEKO-4057`. Public view types constrain both the runtime members and generated declarations; implementation-only overloads are not exposed. Ordinary publication does not require a managed contract or hand-written manifest.

For owner `myaddon`, the stable Binding above is imported as:

```ts
import { Widget } from "nekojs/plugins/myaddon/api/stable";
```

Binding `versioned()` uses `nekojs/plugins/<owner>/api/version`, not `versioned`. Migrate third-party module imports as follows; the old owner-suffix routes are not aliases:

| Previous Binding module | Current Binding module |
|---|---|
| `nekojs/api/stable/<owner>` | `nekojs/plugins/<owner>/api/stable` |
| `nekojs/api/version/<owner>` | `nekojs/plugins/<owner>/api/version` |
| Official `nekojs/api/stable` / `nekojs/api/version` | Unchanged |

Plain `group.server(name, type)`, `client(...)` and `startup(...)` declarations publish versioned events by default, including their dispatch-key overloads. A final configuration callback replaces that default: it publishes only the selected targets, and an empty callback fails with `NEKO-4057`. `group.add(name, scriptType, bus)` without a callback keeps a source private; its configured overload requires at least one publication target. Keyed factories put the callback after the dispatch key, and `add` puts it after the bus.

Configure independent targets beside their shared source definition:

```java
var group = EventGroup.of("MachineEvents");
var changed = group.server("changed", ChangedEvent.class, api -> {
    api.versioned();
    api.stable().view(ChangedView.class, event -> new ChangedView(event.getCount()))
            .scriptTypes(ScriptType.SERVER);
});
// In the plugin event hook:
registry.register(group);
```

The per-event declaration supplies the stable allowlist automatically. `stable()` without a converter uses the source bus's declared payload type as the public view: it must pass portable public-type validation, and runtime access is limited to that type rather than extra members on a delivered subclass. Stable dispatch-key types must also pass portable public-type validation; projecting the payload does not make a native selector portable. The explicit native-bridge exemption described above remains separate.

`stable()` and `versioned()` return the same `EventPublication<E>.Scope` type. Each target independently supports `.view(View.class, converter)` and `.scriptTypes(...)`, in either order. A view converts the payload for that target only; it does not create a new bus or convert the dispatch key. Without `.view(...)`, the target uses the declared source payload. The old `stable(Class, Function)` overload is removed; use `stable().view(Class, Function)`. The builder is frozen when the definition callback returns. Group-wide `EventGroup.expose(...)` is removed; there is no legacy-publication flag.

Stable publication does not require a versioned sibling or a native source. A plugin can own and post an independent portable payload directly:

```java
var ready = group.server("ready", ReadyEvent.class, api -> api.stable());
ready.post(new ReadyEvent(3));

public record ReadyEvent(int count) {}
```

Conversely, `api.versioned().view(ChangedView.class, converter)` can select a versioned payload view. Its converter receives the original `ChangedEvent`, just as a stable sibling's converter does; neither target converts the other's output.

`registry.register(group)` is the sole event registration form. It retains the internal source group and consumes its explicit per-event publication declarations with the current plugin owner; it does not inject a script global. Defining or reading a static GROUP never registers it. Same-owner, same-name source groups merge disjoint event names; duplicate source names fail. Different owners may reuse group and event names because source indexes and module paths are owner-qualified. Disjoint publications with the same owner, category and group name merge into one module export, preserving each event's scope and original bus; duplicate event publications fail.

The configured `registry.register(group, configure)` overload is removed: move publication choices to each source event callback, then register the group once. `.view(...)` on a cancellable source remains rejected for either category until a control mapping is provided; a portable stable source without conversion is not a converted projection. Optional `scriptTypes(ScriptType.SERVER)` restricts a publication to exactly SERVER intersected with source visibility, not the wider SERVER source range (SERVER, STARTUP and TEST). Without an explicit scope, that source range is retained. Scope never widens source availability. Both targets share the source bus, ordering, candidate ownership, rollback and listener cleanup. Subscribing through both targets creates two listeners.

## Release observations

Probe emits `@special/api-modules.json` from the same module registrations. It records the profile, Script Type, category, callable signatures, Bean access and event payload surface. Release tooling can read it with `ApiModuleBaseline.fromJson` and compare an older observation using `old.compareTo(next)`. Stable removals and contractions fail compatibility; version API changes and precise native bridge signature changes are reported separately. These generated observations are author promises, not verified managed contracts or proof of cross-version runtime acceptance.

## Events and current boundaries

Module event subscriptions use the original source bus, priority/order and generation lifecycle. Raw and projected subscription entries reject non-callable listeners synchronously, before collecting a candidate listener or changing the live bus. This input check does not add async support: projected callbacks remain synchronous and must not return a Promise; raw subscriptions retain the source bus's existing callback policy. The per-event callback selects the stable event explicitly; declared and projected public payloads expose only their declared members. Projection does not silently provide native cancellation controls.

### Stable server ticks

Available in SERVER scripts on both NeoForge and Fabric:

```ts
import { ServerEvents } from "nekojs:event/stable";

ServerEvents.tickPre(event => {
  if (event.tick % 20 === 0) console.info("Server tick", event.tick);
});
ServerEvents.tickPost(event => {
  console.info("Completed tick", event.tick);
});
```

The immutable `StableServerTickEvent` payload has one read-only Bean property, `tick`. It snapshots the event server's native `getTickCount()` value; there is no script-owned clock or zero-based rebasing. Supported nodes increment the native count before pre, so the first ordinary tick is 1 and pre/post for the same tick see the same native count. Script reloads do not alter the server count. New-server initialization and integer overflow follow Minecraft rather than an additional counter. Callbacks run synchronously on the server owner thread, use normal event priority/order, and are not cancellable. Retaining the view retains only its numeric snapshot, not a server/native handle. The view exposes no `server` or native cancellation methods. There is no native unwrap for this snapshot.

For native tick payload members, import `ServerEvents` from `nekojs:event/versioned`. An import alias allows the stable and versioned Event Groups to coexist in one script. `NativeEvents` is available through the version Binding module on NeoForge in STARTUP scripts. The supported stable entity conversion methods are on `Native.entities`.
