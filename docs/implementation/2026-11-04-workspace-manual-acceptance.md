## 失败候选测试与入口限制

在测试 fixture imports 后、host 构造前注入 `throw new Error("[NEKO-1003] Intentional CLIENT reload acceptance failure")`。已核对失败日志并保存到 `evidence/window-management-20261104/intentional-reload-failure-client.log`，范围仅为早期候选执行失败，不扩大为全部原生 staging 失败。

最初要求用户在模态打开时按 F3+T，但用户反馈 T 进入输入框，日志也没有新重载。这次尝试记为未执行，不能计通过。随后在有效测试模态中增加用户点击的 `Request CLIENT reload` 按钮，通过已有 Minecraft Binding 的 `getInstance().connection.sendCommand("nekojs reload client")` 发起命令；先让用户准备状态，再注入异常并由用户点击。静态实例入口仅声明 `getInstance()`，连接使用已有 Bean 属性。

自定义面板基于手册回调，测试尺寸为 260×100，按钮行高 28、背景 `#202020`，其余无控件区域用于遮挡检查。“空白”指无子控件，不表示透明；用户指出颜色后已澄清，未将该反馈误计为功能通过。
