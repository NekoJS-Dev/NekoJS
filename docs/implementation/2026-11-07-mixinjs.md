# Experimental MixinJS implementation

## Scope and status

This delivery implements the offline carrier pipeline and root-owned callback runtime from the MixinJS design. It is an experimental development-only implementation, not completion of the design's native-loader or production-mapping acceptance. Installed carriers are rejected in production until that acceptance is completed. No release version was changed.

## Implemented contracts

- `mixins validate|build` extends the existing pack tool. Restricted Graal declaration evaluation accepts finite HEAD/RETURN declarations, static imports from `nekojs/mixin`, and confined relative side-effect imports. Host access, I/O, dynamic imports, exports, asynchronous builders and unbounded statements are rejected.
- Exact target class bytes and descriptors are inspected without class initialization. Profile, source bytes, hook declarations and target bytes contribute to the SHA-256 identity. Constructors, long/BigInt, abstract/native/synthetic/bridge methods and other injector kinds are withheld. ASM is used only by declaration preparation and offline artifact generation, not native dispatch.
- The tool writes modern NeoForge game libraries or dependency-bearing legacy/Fabric carrier JARs, with a dedicated mixin package, exact selectors, plan and original sources. Output is create-new; installation and structural changes require a full restart. Runtime-namespace inputs explicitly disable remapping; this is not a general mapping implementation.
- Runtime discovery sees only loader-admitted plans, validates owner/hash, ABI, exact version/side profile and duplicate IDs, and closes only archive filesystems it opened. Pending declaration files never become runtime hooks or Probe overloads.
- The early bridge has only JDK dependencies and a nullable identity-owned lease. It never creates a root or Context. The generated handler checks enablement before argument boxing/allocation. Native platform adapters verify the real server/client main thread before guest execution; wrong-thread, candidate execution and same-slot reentry bypass the callback.
- Each root owns its slots and reuses EventBusJS candidate registration, duplicate preflight, commit and rollback. Initial loading is transactional only for script types with installed hooks. World teardown revokes callback values; root close detaches only its own lease. One callback is permitted per installed hook.
- Registration requires the actual local candidate entry, an authenticated local callback source URI and a dependency session containing no remote sources. The complete session is checked again at commit, covering remote dependencies loaded after registration. Unknown or virtual callback origins fail closed.
- CommonJS wrappers now use host-built Sources with the resolved file URI, preserving the existing two wrapper lines and executor behavior. A guest sourceURL comment is not treated as source authority.
- Callback controls expire after dispatch and release native references. Invalid writes poison all earlier decisions even when caught in JavaScript. Promise/non-undefined returns and exceptions discard the decision. Primitive ranges, finite floats, one UTF-16 char and assignable native references are checked. HEAD getters may lack a result without permitting null primitive replacement through the TypeScript setter.
- Probe emits precise literal hook IDs only for admitted plans, with readonly receiver/argument slots and controlled return/cancel APIs. The bundled handbook and diagnostics NEKO-4090 through NEKO-4092 document these boundaries.

## Managed loading follow-up

- NeoForge 26.1.2/26.2.0 prepares local declarations before runtime-root creation into manifest-only GAMELIBRARY artifacts, without independent mod-list entries. Manifest MixinConfigs discovery and game-library enumeration use native FML mechanisms. Runtime admission never comes from a raw disk scan.
- Preparation and CLI share the compiler. First preparation, changes and disabling loaded declarations stop startup and require a full restart. Failed compilation preserves the selected artifact. Manual conflicts, missing loader admission, invalid selection data and unowned cache files fail closed.
- A regression with an open JarFile and ZipFS proved that replacing a loaded archive raises AccessDeniedException on Windows. Artifacts are therefore immutable, content-addressed files in the mods directory. A small atomically replaced hash pointer selects the next launch; inactive libraries remain on disk but their plugins disable every injection. They can be removed while the game is stopped. No external helper process, private Sponge mutation or early service-loader hack is used.
- Legacy NeoForge and Fabric retain ordinary mod metadata with mandatory NekoJS dependencies. All newly generated artifacts have a metadata-only early plugin gate: missing NekoJS, exact physical-profile mismatch or production disables injection without linking the runtime bridge. Managed artifacts additionally require the selected hash. This gate never creates a runtime root.
- Bundled handbook and both Wiki languages describe the split workflow and restart/cache boundaries. No version bump is included.

## Remaining acceptance gaps

NeoForge 26.1.2 development discovery, Sponge transformation and one dedicated-server callback have been demonstrated as recorded above. Full client/dedicated-server isolation, the native ABI/control matrix, legacy/Fabric live-loader dependency behavior, orphan-library behavior without NekoJS, and production namespace/mapping acceptance remain unverified. These are release blockers, not inferred successes from classfile or common runtime tests. Development runtime names are the only tool namespace currently accepted. Relative declaration imports do not support exported helpers. Discarding a callback decision rolls back its return/cancel control writes, not arbitrary side effects performed through native objects by locally trusted code. No maintainer acceptance or production support is claimed.
