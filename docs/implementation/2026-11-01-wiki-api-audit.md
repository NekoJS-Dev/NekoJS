## Implemented object-style public APIs

### Post-effect declarations: highest-priority configuration migration candidate

**Current executable shape** (NeoForge client implementation; not a proposed builder):

```js
ClientEvents.postEffects(event => {
    event.register('example:soft_blur', { blurRadius: 4, blurRounds: 1 });
});
```

[PostEffectEventJS.java:52–113](<../../src/main/java/com/tkisor/nekojs/client/posteffect/PostEffectEventJS.java#L52-L113>) defines exactly `public boolean register(String id, Map<String, Object> options)`. The options are `chainJson`, `fragmentShader`, `fragmentShaderId`, `fragmentShaders`, `vertexShaders`, `uniformsJson`, `blurRadius`, `blurRounds`. The parser selects **chainJson before fragmentShader before blurRadius**, rather than rejecting simultaneous modes. GLSL and chain/uniform JSON are strings; `uniformsJson` is not an ordinary JS object parameter. Null options become an empty map; missing all modes records an error and returns false. True means collected, not already rendered/committed.

Concrete awkwardness, not merely aesthetic preference:

- The public map signature hides a finite schema and mutually exclusive modes from Java reflection. `@Doc`/`@Param` text supplies prose, not a typed Java options model.
- Unknown keys are not rejected. [PostEffectEventJS.java:141–163](<../../src/main/java/com/tkisor/nekojs/client/posteffect/PostEffectEventJS.java#L141-L163>) accepts only Java String/Number at scalar helpers and silently drops non-string key/value pairs from source tables. Mistyped optional fields can disappear instead of receiving field-specific diagnostics.
- The chain JSON/GLSL/source-table payloads remain legitimate data even if the outer definition API changes. Do not replace arbitrary JSON contents with invented Java properties.

Existing lifecycle is important: invalid declarations fail the batch at preflight and retain the old active generation; `unregister(id)` records retirement at commit, not immediate deletion ([PostEffectEventJS.java:65–66](<../../src/main/java/com/tkisor/nekojs/client/posteffect/PostEffectEventJS.java#L65-L66>), [PostEffectEventJS.java:116–131](<../../src/main/java/com/tkisor/nekojs/client/posteffect/PostEffectEventJS.java#L116-L131>)). A style migration must preserve that behavior.

**Proposed shape only — not callable today:** `event.register(id, build => { /* typed configuration */ })`. This means adding a new typed configuration-callback overload or making an explicitly authorized breaking replacement, not documenting an existing method. The builder should model mutually exclusive modes, validate unknown/wrong-typed inputs at the boundary, and retain raw JSON/GLSL data escape hatches. No builder class, setters, property names or extra `build()` method are promised here.

Availability: [ClientEvents.java:133–134](<../../src/main/java/com/tkisor/nekojs/bindings/event/client/ClientEvents.java#L133-L134>) declares the client bus. [NekoPostEffectPlugin.java:1–22](<../../src/main/java/com/tkisor/nekojs/client/posteffect/NekoPostEffectPlugin.java#L1-L22>) is NeoForge-guarded, client-only and registers the separate `PostEffects` binding for **exact** `ScriptType.CLIENT`. Do not infer Fabric support from a shared/common declaration, or expose old `PostEffects.register` merely because the declaration Javadoc mentions a previous API.

### HUD/world registration: configuration object plus a different kind of callback

**Current syntax**, from [RenderRegistrationBusJS.java](<../../src/main/java/com/tkisor/nekojs/client/render/RenderRegistrationBusJS.java>):

```js
ClientEvents.hudRender('example:hud', drawCallback);
ClientEvents.hudRender('example:hud', { layer: 'foreground', priority: 10 }, drawCallback);
ClientEvents.worldRender('example:world', { layer: 'late', priority: 10 }, drawCallback);
```

`drawCallback` here is a placeholder for the caller's render function. The final function is retained for **frame-time drawing**, not executed as a configuration builder. There are also actual three-argument shorthands with a middle layer string or numeric priority. Arity is 2 or 3, id must be a nonblank string, and the last argument must be executable. Default layer is normal and priority is zero. HUD layers are background/normal/foreground; world layers early/normal/late ([RenderRegistrationBusJS.java](<../../src/main/java/com/tkisor/nekojs/client/render/RenderRegistrationBusJS.java>)).

Object keys with wrong types are ignored; unknown keys are not checked; numeric priorities truncate through `(int) options.asDouble()`. A valid but wrong-layer spelling throws. This is a finite configuration surface worth typing, but the existing **drawing callback cannot just be renamed `build`**. Registration captures the callback's Context/script id and passes it to the generation-owned render registry.

**Proposed shape only — not callable today:** `ClientEvents.hudRender(id, drawCallback, build => { /* typed layer/priority */ })` (and world equivalent), if maintainers choose config-last semantics. This would be a deliberately new overload/contract: today's parser interprets argument two as options and argument three as the drawing function. Do not run this proposal against current code. An alternative explicit definition-builder design needs an actual renderer setter and tested declarations before any such member is documented; none is invented here.

NeoForge platform handlers map the registered renderers to stages ([ClientRenderEvents.java:1–79](<../../src/main/java/com/tkisor/nekojs/client/render/ClientRenderEvents.java#L1-L79>)). [ClientEvents.java:151–161](<../../src/main/java/com/tkisor/nekojs/bindings/event/client/ClientEvents.java#L151-L161>) registers the entries under ClientEvents, not a second event group. Existing surface tests distinguish them from plain `hud`/`screenRender` listeners and pin CLIENT ScriptType ([Ticket27ClientGuiRenderSurfaceTest.java:58–95](<../../src/test/java/com/tkisor/nekojs/client/render/Ticket27ClientGuiRenderSurfaceTest.java#L58-L95>)); the catalog test explicitly excludes unimplemented renderer-registration entries on Fabric ([Ticket27ClientGuiRenderSurfaceTest.java:183–199](<../../src/test/java/com/tkisor/nekojs/client/render/Ticket27ClientGuiRenderSurfaceTest.java#L183-L199>)). Do not generalize “all ClientEvents absent on Fabric” from this narrower exclusion.

### Trade declarations: typed outer builder is possible; trade/item records are still data

**Current**: `ServerEvents.tradeDeclaration(event => event.add('minecraft:farmer/level_1', { cost: '1x minecraft:emerald', result: '5x minecraft:apple', maxUses: 12, xp: 2, priceMultiplier: 0.05 }))`.

[VillagerTradeDeclarationEventJS.java:34–77](<../../common/src/main/java/com/tkisor/nekojs/core/villager/VillagerTradeDeclarationEventJS.java#L34-L77>) defines `add(String tradeSet, Object config)`, add-only. Required cost/result, optional costB, default maxUses 12, xp 2 and priceMultiplier 0.05 are read by name. The item forms are strings (including count prefix) or `{ item, count }`; positive count is required; numeric optional fields accept Number-like values and truncate int fields, while wrong-typed optional numbers fall back ([VillagerTradeDeclarationEventJS.java:87–138](<../../common/src/main/java/com/tkisor/nekojs/core/villager/VillagerTradeDeclarationEventJS.java#L87-L138>)). Unknown config keys are not rejected. A typo in an optional setting may therefore use a default rather than fail.

This outer declaration is another possible typed callback candidate, **not proof that the nested item record is inappropriate**. Proposed shape only: `event.add(tradeSet, build => { /* typed trade configuration */ })`; no such callback overload is claimed. Before migration choose whether the outer shape is intentionally a serializable trade record; prioritize strict validation and generated input types even if its object form remains.

Platform/type distinctions: the production bus is SERVER and describes candidate DOMAIN_PLAN/server-start collection, with mutation only at adapter commit ([ServerEvents.java:91–108](<../../src/main/java/com/tkisor/nekojs/bindings/event/ServerEvents.java#L91-L108>)). The declaration Javadoc distinguishes 26.x trade-set registry ids from 1.21.1 profession/level and wandering-trader pool ids; common code alone does not prove node support. The NeoForge-guarded helper plugin binds `VillagerTrades` for exact SERVER ([VillagerTradesPlugin.java:1–33](<../../src/main/java/com/tkisor/nekojs/villager/VillagerTradesPlugin.java#L1-L33>)); its current public helper only has `query()`/`describe()`, not direct add/remove/replace methods ([VillagerTradesJS.java:10–30](<../../src/main/java/com/tkisor/nekojs/bindings/static_access/VillagerTradesJS.java#L10-L30>)).

### Custom event declaration: an existing positional alternative, not a new builder requirement

[ScriptEventRegistrationEvent.java:8–47](<../../common/src/main/java/com/tkisor/nekojs/api/event/ScriptEventRegistrationEvent.java#L8-L47>) already supports both `event.register('MyEvents', 'bossKilled')` and `event.register({ group: 'MyEvents', name: 'bossKilled' })`. The latter requires an object and string group/name, explicitly rejects non-null `event`/`eventClass`, and does not globally validate every other unknown key. Prefer the existing positional form when teaching this simple two-name operation; do not claim the object form was removed. [ScriptEvents.java:5–15](<../../common/src/main/java/com/tkisor/nekojs/api/event/ScriptEvents.java#L5-L15>) places declarations in STARTUP buses, creating target SERVER/CLIENT custom events. These are not arbitrary loader-native event classes and not permission to mutate a frozen group.

## Objects that should not be swept into a builder rewrite

- **Recipe filters are a predicate language**, not definition configuration. [RecipeFilterAdapter.java:17–56](<../../src/main/java/com/tkisor/nekojs/js/type_adapter/RecipeFilterAdapter.java#L17-L56>) declares string/array/object forms and 12 keys: not/and/or/output/input/mod/group/id/idStartsWith/idEndsWith/idContains/type. [RecipeFilterAdapter.java:65–110](<../../src/main/java/com/tkisor/nekojs/js/type_adapter/RecipeFilterAdapter.java#L65-L110>) maps strings to id, arrays to OR, object conditions to AND; rejects unknown keys/unsupported values. Empty object intentionally means unconstrained matching. Replacing this with generic builder advice would obscure a real data contract (and broad deletion risk).
- **Recipe JSON, shaped-key maps and dynamic schemas are data.** [RecipeEventJS.java:524–562](<../../src/main/java/com/tkisor/nekojs/wrapper/event/server/RecipeEventJS.java#L524-L562>) implements `custom(String, RecipeJsonValue)`, `custom(RecipeJsonValue)`, `custom(JsonObject)` and `shaped(ItemStack, List<String>, Map<String, Ingredient>)`; the JSON must be an object and type is injected in the typed custom form. Keys such as shaped symbols are not a finite configuration-property API. Query/mutation uses actual filters/callbacks ([RecipeEventJS.java:438–499](<../../src/main/java/com/tkisor/nekojs/wrapper/event/server/RecipeEventJS.java#L438-L499>)). Preserve schema-driven mod-specific fields and raw JSON fallback rather than inventing hard-coded methods for every recipe.
- **JSX props are syntax/runtime data**, not automatically an event-definition smell. [NekoJsxCompiler.java:15–32](<../../common/src/main/java/com/tkisor/nekojs/core/compiler/NekoJsxCompiler.java#L15-L32>) explicitly implements classic factory vs automatic jsx/jsxs/Fragment transforms with children in props. JSX and UI behavior require their own lifecycle/typing audit; a blanket object ban would change language semantics.
- **MCP JSON is a wire contract**, not a Script API builder. [AuthoringMcp.java:118–161](<../../common/src/main/java/com/tkisor/nekojs/authoring/AuthoringMcp.java#L118-L161>) dispatches JSON-RPC methods and publishes JSON inputSchema/annotations. Its object envelopes must remain interoperable. This audit does not authorize MCP transport, permission or schema changes.
- Adapter input records, JSON/NBT/components, source tables, predicate expressions and callback event payloads should be judged by their own data semantics. Presence of braces alone is neither a design defect nor provenance proof.
