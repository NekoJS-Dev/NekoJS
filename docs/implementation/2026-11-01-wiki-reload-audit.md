## Cross-cutting contracts and limitations

- No filesystem watcher/autoReload/debounce implementation was found in the inspected common/platform source paths. Internal HMR naming means module identity/dependency invalidation here, not save-to-reload; no watcher configuration was invented. Manual full/file/pack operations, server data reload and client resource reload are separate.
- Candidate commit protects managed generation/state/listener/timer publication, not arbitrary Java/world/filesystem effects or deep mutation of shared objects. Candidate timers can execute while awaited during candidate evaluation; they are not claimed to be universally dormant until commit. Failed candidates discard their pending resources.
- The synchronized internal owner entry executes the callable inline. It is not a dedicated-thread marshaller; common concurrency tests do not establish platform render/server thread affinity.
- Legacy non-guest global/shared values can outlive generation and world transitions until root close. Guest values expire with their owning generation. Versioned private global instead follows pack/source/session lifetime. The common state test world-stop leg is structural and does not substitute for a live world-switch test.
- Current event.recipes namespace proxies are not a demonstrated removed Katton API. Exact third-party recipe constructors depend on installed schema/handlers; modloaded:create alone is not proof. The directive sample no longer depends on such a constructor.
- Native filesystem policy remains narrower for writes than reads. Enabling the write-expansion flag never permits leaving the game directory or modifying protected engine configuration. HostAccess and optional execution budgets do not make untrusted scripts safe; watchdog/statement defaults remain zero.
- Synchronous require may return an already evaluated ESM namespace before its async check; documentation rejects not-yet-evaluated asynchronous ESM rather than claiming every TLA module is always impossible to require. The package.json resolution and parser-warning findings are production-path evidence; no dedicated regression asserting those absences was inspected.

## Proposed refactors (not implemented)

1. A shared typed reload-result description could keep command, authoring control and documentation aligned on generation commit versus post-commit recipe/data follow-up. This is a future production change, not behavior added by this audit.
2. Focused tests for invalid inline priority values, package.json entry rejection and STARTUP timer exclusions would make these existing boundaries harder to regress. No gate was weakened or test result invented.
