## The original algorithm: nominal TypeInfo first, not expanded JSON shapes

1. [RecipeEvents:54–84](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/plugin/builtins/events/RecipeEvents.java#L54-L84>) walks live server recipe schemas, skips unknown/hidden/unregistered serializer profiles, and creates a recipe declaration plus namespace method.
2. [Method generation:122–136](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/plugin/builtins/events/RecipeEvents.java#L122-L136>) loops `schema.keys`, skips excluded keys, skips keys with empty functionNames, converts `key.component.typeInfo()`, marks it as input, and uses `key.optional()` for the parameter optional flag. It generates one key-order method; it does **not** use schema constructor metadata. Reuse the type model, not this constructor omission: it explains original EnderIO zero-argument and Mekanism constructor discrepancies.
3. [Builder generation:139–165](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/plugin/builtins/events/RecipeEvents.java#L139-L165>) extends the actual schema factory recipe subtype. Generated setters and custom schema functions use component/argument TypeInfo, return this, and preserve custom subtype members through inheritance. NoFunctions suppresses autogenerated setters; it does not make mandatory runtime constructor fields disappear.
4. [TypeConverter:26–75](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/typescript/transpiler/TypeConverter.java#L26-L75>) maps class/primitive, array, variable, parameterized, union, and literal TypeInfo into a neutral Type tree. Raw generic classes get any-filled parameters (:45–47). ParameterizedTypeInfo preserves raw class plus independently converted arguments (:59–68). JSOrTypeInfo becomes a union (:70–72), not an invented domain alias. NONE becomes never. Optional<T> becomes a distinct OptionalType. ClassWrapper<T> becomes typeof T.
5. [ParamType:19–41](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/typescript/document/types/ParamType.java#L19-L41>) collects imports recursively from raw base and every type argument, then formats Base<Args>. [InputAliased:24–46](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/typescript/document/base/InputAliased.java#L24-L46>) selects the registered underscore symbol/import only in input context.

Input marking is selective, not blanket underscore rewriting. [Types.markAsInput:129–157](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/typescript/document/Types.java#L129-L157>) marks registered aliases or eligible records; recurses through arrays, Optional, parameterized base and ordinary type arguments; but retains nominal arguments for functional interfaces and registry holders. [Holder types:46–55](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/plugin/builtins/alias/RegistryTypes.java#L46-L55>) identifies Holder, TagKey, ResourceKey and HolderSet. This is why ResourceKey<LevelStem> keeps its domain argument instead of input-converting LevelStem.

## List, union, spread, and optional semantics

- Original [ListRecipeComponent:39–52](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/recipe/component/ListRecipeComponent.java#L39-L52>) constructs `RAW_LIST.withParams(element.typeInfo())`. Only `canWriteSelf=true` additionally unions the scalar element TypeInfo. Dynamic metadata defaults can_write_self to false at [lines66–72](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/recipe/component/ListRecipeComponent.java#L66-L72>). List cardinality is a component contract, not a renderer heuristic.
- [EitherRecipeComponent:24–26](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/recipe/component/EitherRecipeComponent.java#L24-L26>) declares `left.typeInfo().or(right.typeInfo())`; original TypeConverter preserves that union structurally.
- Spread/spreadWrap remains separate component wrapping data in [lines50–63](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/recipe/component/ListRecipeComponent.java#L50-L63>), not an extra nominal list-element type. Runtime counted ingredient expansion can exist without being printed as another TypeInfo domain.
- Original [collection aliases:29–36](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/plugin/builtins/alias/JavaPrimitiveTypes.java#L29-L36>) registers List<E> input alias E[]. The actual [original List alias:642](<D:/Minecraft/.minecraft/versions/1.21.1-kubejs-test/.probe/@package/java/util/index.d.ts#L642>) is `$List_<E> = E[]`, not SingleOrArray and not a scalar. Native [current native List alias:1478](<D:/mcmodDemo/NekoJS-mult/addons/nekujs/build/run/testClient/.neko_probe/typescript/@package/java/util/index.d.ts#L1478>) additionally retains Java `$List<E>` hosts. Host-list support is a native conversion choice; neither alias implies accepting a single E.
- Recipe optionality is parameter syntax: [ParamDecl:39–47](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/typescript/document/members/ParamDecl.java#L39-L47>) prints `name?: Type`. This differs from Java Optional<T>, which [OptionalType:18–30](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/typescript/document/types/special/OptionalType.java#L18-L30>) renders as `(T) | undefined`. Do not infer either from a nullable JSON default alone.

## Exact ownership of Create cutting

Primary [Create extension archive](<D:/Minecraft/.minecraft/versions/1.21.1-kubejs-test/mods/kubejs-create-neoforge-2101.3.1-build.18.jar>) entries (decoded directly, no extraction):

- `data/create/kubejs/recipe_schema/cutting.json`:2 inherits create:base/processing_with_time.
- `base/processing_with_time.json`:2 inherits base/processing; :3–10 overrides processing_time as ticks, optional 100, always_write true.
- `base/processing.json`:4–13 defines results = list(either(fluid_stack,create:processing_output)); :16–30 defines ingredients = list(either(create:sized_fluid_ingredient,ingredient)), with separate sized-ingredient spread; no can_write_self is specified. :33–43 defines optional time and excluded optional heat; :47–57 defines heated/superheated set functions.

Therefore the original type model is `List<FluidStack | ProcessingOutput>` and `List<SizedFluidIngredient | Ingredient>`, plus optional TickDuration. Its alias registry then selects FluidStack_ and Ingredient_ where registered; it does not derive structural result aliases from `{id,count,chance}`. [Recipe value aliases:33–49](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/plugin/builtins/alias/RecipeTypes.java#L33-L49>) and [Fluid aliases:67–77](<D:/mcmodDemo/NekoJS/ProbeJS-1.21/src/main/java/moe/wolfgirl/probejs/plugin/builtins/alias/RecipeTypes.java#L67-L77>) own supported alternative inputs. Original generated [representative processing methods:122–127](<D:/Minecraft/.minecraft/versions/1.21.1-kubejs-test/.probe/@side-only/server/events/recipes/index.d.ts#L135>) confirms the resulting compact nominal signature. SizedFluidIngredient and ProcessingOutput remain bare nominal symbols there, not automatically suffixed input aliases.

## Minimal mapping to NekoJS: reuse the model, preserve runtime truth

1. Add optional neutral declaration metadata to the existing field codec/catalog seam, populated in the version-facing addon from actual RecipeComponent.typeInfo. Preserve class symbols, generic arguments, List cardinality, union/literal alternatives and raw generic arity in ApiTypeRef. Do not reverse-engineer nominal domains from codec JSON shape or field names.
2. Render that metadata through existing [native IR input rendering:944–1010](<D:/mcmodDemo/NekoJS-mult/common/src/main/java/com/tkisor/nekojs/probe/ir/TypeScriptClassRenderer.java#L944-L1010>) and canonical [collection input rendering:196–220](<D:/mcmodDemo/NekoJS-mult/common/src/main/java/com/tkisor/nekojs/probe/types/TypeAliasRegistry.java#L196-L220>). Registered converters decide underscore aliases; inputs retain real nominal generic arguments according to existing Neko policies. No new SingleOrArray or whole-field/domain wrapper aliases are needed.
3. Missing nominal metadata should keep the existing inline input shape, not create substitute wrappers. Retain exact codec shapes independently for runtime validation and input-acceptance documentation. A declaration-type change does not authorize broadening runtime conversion.
4. Continue using native schema constructors, defaults, forced overrides, noFunctions and subtype validation. Do not copy the original RecipeEvents key-loop constructor defect. Keep native runtime owner and Graal HostAccess visibility, not Rhino reflection-cache semantics.
5. Collect dependencies from complete typed references, including nominal generic arguments and alias bodies; imported nominal types must participate in the existing emitted declaration closure. Tests should cover cutting List/Union types, host lists, canWriteSelf false/true, optional parameters separately from Optional<T>, record/holder generics and callback argument identity.
