# KubeJS 注册表扩展：选择器、Builder 与原生表

**KubeJS 2101 插件可以给 `minecraft:item` 加 Builder 类型，但不是通过插件“注册 `item` 选择器”。** `item` 本来就是原生表键 `minecraft:item` 的简写。模组可以用 NeoForge 建立自己的静态表，再用 KubeJS 插件提供工厂；脚本按完整键订阅。这是两个不同的扩展动作。

依据：本地 KubeJS 2101.7.2（Minecraft 1.21.1 / NeoForge 21.1.199，[版本配置](<D:/kubejs-2101/gradle.properties#L12-L19>)）、NeoForge 1.21.1 分支源码和当前 NekoJS 工作树。仅核查源码，未运行游戏或测试。

## KubeJS 2101

1. **selector 是原生表键。** [StartupEvents](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/plugin/builtin/event/StartupEvents.java#L14-L20>) 的 `registry` 必须带 target。[EventTargetType.REGISTRY](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/event/EventTargetType.java#L28-L33>) [把字符串解析为 `ResourceKey.createRegistryKey(ResourceLocation.parse(...))`](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/event/EventTargetType.java#L97-L122>)，也接受现成的 `ResourceKey`；这里不查工厂目录、别名表或原生表是否存在。`item` 和 `minecraft:item` 同键；语法合法的未知键能挂监听，但没有对应 pass 就不会投递。内置插件[注册并注入 `StartupEvents` 组](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/plugin/builtin/BuiltinKubeJSPlugin.java#L398-L419>)，也不是往该组登记 selector 值。
2. **插件加的是 Builder，脚本加的是条目。** [KubeJSPlugin.registerBuilderTypes](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/plugin/KubeJSPlugin.java#L47-L67>) 接收 [BuilderTypeRegistry](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/registry/BuilderTypeRegistry.java#L10-L26>)：`addDefault(key, class, factory)` 设置默认工厂，`of(key, cb)` 的 `cb.add(typeId, class, factory)` 添加命名类型。[BuilderTypeRegistryHandler](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/registry/BuilderTypeRegistryHandler.java#L21-L29>) 惰性汇总成 key → Info；[同名类型／默认工厂被覆盖时会告警；命名 lookup 先用完整 ID，再按 path 回退](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/registry/BuilderTypeRegistryHandler.java#L39-L107>)。内置主插件通过同一 API 为 `Registries.ITEM` 设置 `ItemBuilder`，加 `kubejs:sword` 等；[stock 清单](<D:/kubejs-2101/src/main/resources/kubejs.plugins.txt#L1-L3>)里的[客户端插件](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/plugin/builtin/BuiltinKubeJSClientPlugin.java#L22-L43>)注册客户端事件／Binding，[Architectury 集成](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/integration/architectury/ArchitecturyIntegration.java#L9-L17>)提供类型转换。[ITEM 工厂示例](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/plugin/builtin/BuiltinKubeJSPlugin.java#L327-L342>)。[RegistryKubeEvent](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/registry/RegistryKubeEvent.java#L23-L119>) 的 `create(id)` / `create(id, type)` 取默认／命名工厂并暂存 Builder；`createCustom(id, supplier)` 不查工厂目录。原生对象最终由[当前 pass 的 `RegisterEvent.register`](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/registry/RegistryEventHandler.java#L35-L57>)提交。
3. **创造新键不等于安装新静态表。** `ResourceKey.createRegistryKey` 只构造键，`BuilderTypeRegistryHandler.of` 只创建 Info；为 `addon:machine` 登记任意多工厂也不会触发投递。宿主模组在 mod bus 的 [NeoForge NewRegistryEvent](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/registries/NewRegistryEvent.java#L18-L75) 用 `RegistryBuilder` 创建并安装原生表。NeoForge 的 [GameData](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/registries/GameData.java#L80-L95) 对原生表发 `RegisterEvent`，[顺序包含模组表](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/registries/GameData.java#L117-L134)。KubeJS 的[通用 handler](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/registry/RegistryEventHandler.java#L23-L39>) 不限原版键；已安装的模组表可以订阅 `StartupEvents.registry("addon:machine", ...)`，有相应工厂才有对应的 `create` 路径，也可以提供 supplier。无需另注册 selector。
4. **数据包表走 SERVER，不走静态 pass。** 真正的新表由 NeoForge mod bus 的 [DataPackRegistryEvent.NewRegistry](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/registries/DataPackRegistryEvent.java#L36-L75) 声明键、磁盘 codec 和可选网络 codec，和[静态表的安装](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/registries/RegistryManager.java#L78-L97)分开。KubeJS 的 `registerServerRegistries` 只给 Info 填 `directCodec` 和 `TypeInfo`，如 stock 的 `BIOME`、`ENCHANTMENT`、`JUKEBOX_SONG`；不向 NeoForge 声明新表。[stock 列表](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/plugin/builtin/BuiltinKubeJSPlugin.java#L368-L396>)、[实际写入](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/registry/BuilderTypeRegistryHandler.java#L65-L75>)。`ServerScriptManager` 仅在当前 manager 的 `firstLoad` 遍历 NeoForge 的 `DataPackRegistriesHooks.getDataPackRegistries()`，用上游 `elementCodec` 投递 `ServerEvents.registry`、把条目编码进虚拟数据包，再由 Minecraft 读取。`createFromJson` 也使用该上游 codec。STARTUP 的显式类型 `create(id, type)` 检查 `directCodec` 并拒绝；默认重载没此检查，但不会因此得到静态 pass。[SERVER 投递](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/server/ServerScriptManager.java#L183-L224>)、[编码写入](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/server/ServerScriptManager.java#L234-L265>)、[安装虚拟包](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/server/ServerScriptManager.java#L62-L81>)、[createFromJson](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/registry/ServerRegistryKubeEvent.java#L87-L95>)、[STARTUP 重载](<D:/kubejs-2101/src/main/java/dev/latvian/mods/kubejs/registry/RegistryKubeEvent.java#L29-L72>)。

## NekoJS 的对应边界

- **已有 Builder 扩展点。** `RegistryTypesPoint.Contributor` 可添加 `registerType(key, name, builderClass, factory)` 和 `setDefault(key, name)`，提供 Builder class 才能派生具体声明。内置插件已给 `Registries.ITEM` 贡献默认 `basic`；现有测试源码覆盖外部命名工厂和显式／默认声明，不是实机注册验证。[工厂与默认类型](<../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryTypesPoint.java#L39-L91>)、[内置贡献](<../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/NekoRegistryPointsPlugin.java#L54-L79>)、[贡献测试](<../../src/test/java/com/tkisor/nekojs/wrapper/registry/gen/StartupRegistryDefaultDeclarationsTest.java#L127-L153>)。
- **已有表键元数据扩展点。** `RegistryInfosPoint.Contributor` 提供 `addClassToScan` / `addInfo`：先扫插件贡献类、再扫原版 `Registries`，最后并入手工条目，按键先到先得。两个 Point 都由版本树插件安装，按 Contributor 收集；不需要在 `common` 增加 Minecraft 类型钩子。现有低层 `event.register(registry, id, supplier)` 可通过目录识别贡献的完整键，但能识别并暂存，不代表原生提交成功。[infos 收集](<../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryInfosPoint.java#L42-L108>)、[Point 注册](<../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/NekoRegistryPointsPlugin.java#L29-L51>)、[Contributor 派发](<../../common/src/main/java/com/tkisor/nekojs/core/plugin/NekoPluginBootstrap.java#L157-L179>)、[目录](<../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryEventJS.java#L59-L78>)、[supplier 入口](<../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryEventJS.java#L184-L208>)。
- **NeoForge** 随原生 `RegisterEvent` drain，加载完成时报告没有 pass 的暂存项；已由其他模组建好的静态表有按键消费路径，但跨表派生仍受 pass 顺序约束。**Fabric** 在初始化时 drain（非 ITEM 在前），查 `BuiltInRegistries.REGISTRY` 再调用 `Registry.register`；缺表直接报错，不建表。自定义静态表至少要在 drain 前安装到该根表且可写，未实机验证此组合。原版数据包表不走这两条静态路径，附魔是已有 Builder 却没有静态 sink 的例子。NekoJS 实验性 `DynamicRegistryEvents` 也不是数据包表扩展，仅为 NeoForge 26.x 的 Item/SoundEvent/MobEffect 提供另一条受限写入路径。[NeoForge adapter](<../../src/main/java/com/tkisor/nekojs/listener/RegistryEventAdapter.java#L61-L76>)、[Fabric drain](<../../src/fabric/java/com/tkisor/nekojs/fabric/FabricRegistryAdapter.java#L71-L119>)、[附魔移植记录](<../fabric-port-status.md#L119-L121>)、[实验性动态 adapter](<../../src/main/java/com/tkisor/nekojs/dynamic/NeoForgeDynamicRegistryAdapter.java#L23-L45>)。

**本轮计划边界：** `item` / `minecraft:item` 指向同一个已有静态键。新旧入口共用[一次启动收集](<../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/StartupRegistryRuntime.java#L118-L139>)、工厂与暂存，无需新增 selector 注册钩子。若以后开放插件贡献的其他表作为 selector，应验证目录元数据、所需工厂以及该节点实际可提交；不能只看扫描出的键或生成声明。真正新增静态表或数据包表，分别按加载器能力验收。脚本接口细节见[对照笔记](<kubejs-startup-registry.md>)。
