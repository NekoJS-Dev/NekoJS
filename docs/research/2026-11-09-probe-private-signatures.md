# Probe public-method discovery and unavailable private signatures

## Observed failure

The supplied Create 6.0.10 station class loaded, but its declaration was omitted with NEKO-4038. The unchanged class contains a private static synthetic `lambda$registerCapabilities$1(StationBlockEntity, Direction): IPeripheral`. ComputerCraft was absent. `Class.getDeclaredMethods()` resolved that private implementation signature before the later public-member filter, throwing `NoClassDefFoundError: dan200/computercraft/api/peripheral/IPeripheral`. The real public method signatures did not require that type.

## Implementation

[TypeReflector](<../../common/src/main/java/com/tkisor/nekojs/probe/ir/TypeReflector.java>) now starts public declaration discovery with `Class.getMethods()`, selecting owner-declared candidates from the native result and retaining the existing inherited-overload and interface selection policies. Interface candidate collection follows the same public-only rule. The shared class collector and both declaration backends already use this seam.

This is VM-level public filtering before private signature resolution, not a catch-and-ignore path. Reflected Method identity, generic metadata, annotations, Bean/remap policies and source edits remain native. No ComputerCraft stub, guessed API, erased replacement, additional dependency or raw-byte declaration source was added. Mixin implementation-member discovery is a different contract and is unchanged.

## Verification scope

- Regression-first testing used the unchanged supplied Create JAR and its actual nested runtime libraries, without ComputerCraft or initializing the station class. The old shared reflector failed after the native public-method baseline succeeded; the corrected reflector and real TypeScript renderer retain the station declaration and public station/capability methods.
- Shared regressions exercise an owner and interface with unavailable private synthetic signatures, Bean accessors, inherited overload identities, class-initialization avoidance, and actual TypeScript/Python backend output.
- This private-signature increment did not recover unavailable public signatures. The later [public-contract followup](<2026-11-09-probe-public-contracts.md>) retains independently verifiable members with an explicit incomplete-method report. It still does not promise success for unavailable constructor, field, superclass or side-restricted public types.

Final gates passed: `guardLint`, `:common:check`, `:1.21.1:build`, the addon build and all fixture/historical-proof tests, source-root isolation (two Java and six resource roots), and `pnpm run test:probe-types`. The four shared regressions and the unchanged Create fixture passed without failures or skips. Independent read-only review and scoped whitespace checks passed. The backend regression positively retains honest private Mixin diagnostics while requiring a complete public closure and typed public output.

The existing game-generated output was inspected but not hand-patched or regenerated by these tests. Restart the development client to load rebuilt classes, then run `/nekojs probe` (TypeScript) or `/nekojs probe all` (both languages). `/nekojs probe reload` only reloads Probe configuration. The [subsequent public-contract repair](<2026-11-09-probe-public-contracts.md>) addresses the five identified engine-type leaks without exposing engine packages; neither change makes the complete report unconditionally true.
