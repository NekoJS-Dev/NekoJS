# Kubeloader 源码参照

日期：2026-10-14。源码基线：`WhiseNT/kubeloader` commit `1f5222c049ccdb0fd256e1bace9385176a59c6ba`。本报告只核对该版本的实现与调用路径；未运行构建、脚本或游戏。

## 结论

- `ContentPack` 是接入 KubeJS `ScriptPack` 的适配层：Provider 提供包，`PackLoadingContext` 携带当前 `ScriptManager`/`ScriptType`，适配器为该类型构造或缓存 `ScriptPack`。它不是一个独立的脚本加载器协议。[接口与加载上下文](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/definition/ContentPack.java#L9-L38)、[上下文](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/definition/PackLoadingContext.java#L10-L42)
- GraalJS 分支的包隔离是真实创建独立 `Context`，索引为当前 `ScriptManager` 的 `ScriptType` 管理器实例内的包 namespace；`ScriptPack` Mixin 只是保存 Context 的字段。Rhino 仍由 KubeJS `ScriptManager`/`ScriptPack` 路径执行，不能把 Graal Context 方案概括为整个系统唯一的隔离模型。[Context 创建与附着](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/graal/GraalScriptManager.java#L13-L47)、[包装字段](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/mixin/ScriptPackMixin.java#L11-L34)
- 这些 Graal Context 不是包级权限边界：每个 Context 复制同一 ScriptType manager 的 bindings；`ContentPacks` 再公开全部已发现包的元数据，并提供按 ScriptType（不是按包）索引的静态共享表。[Bindings 注入](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/graal/GraalApi.java#L265-L301)、[ContentPacks API 与共享表](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/plugin/ContentPacksBinding.java#L17-L112)
- 可借鉴的是显式包元数据和有类型的依赖/顺序声明；不要移植其宽泛 Graal host access、Context map 生命周期或 Provider 注册结构作为 NekoJS 的新运行时所有权。NekoJS 应沿自己的 Point、Plugin Hook、Contributor 和 `NekoRuntimeRoot` 约定评估产品接口。

## 发现和包接口

`ContentPackProvider.providePack()` 返回一组 `ContentPack`；默认视为 dynamic，每次取包重新查询；static provider 首次取包后缓存。内建路径 provider 与 dummy provider 使用默认 dynamic，mod provider 也显式 dynamic。管理器每次加载都取 providers、校验元数据、按 `id` 建索引，再请求当前类型的 `ScriptPack`。无效重复 ID 或依赖验证错误时跳过 ContentPack 加载并返回原 KubeJS packs。[Provider 合约](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/definition/ContentPackProvider.java#L10-L26)、[缓存与动态查询](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/impl/ContentPackProviders.java#L11-L55)、[ScriptManager 接入](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/mixin/ScriptManagerMixin.java#L60-L141)

`ContentPackBase` 会按 `ScriptType` 缓存生成的 `ScriptPack`。`PackLoadingContext` 是对现有 manager 的薄包装，提供类型、目录名、console 和委派的 `loadFile`；它本身不持有独立 JS Context、事务或资源 owner。[基类缓存](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/impl/ContentPackBase.java#L17-L39)、[上下文委派](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/definition/PackLoadingContext.java#L19-L42)

`contentpack.json` codec 字段为 `id`、可选名称/描述/版本、作者和依赖。依赖包含来源 `PACK`/`MOD`、ID、版本范围、理由、顺序；类型区分 `REQUIRED`、`OPTIONAL`、`RECOMMENDED`、`DISCOURAGED`、`INCOMPATIBLE`。校验器按 Maven `VersionRange` 检查包或已加载 mod：缺失 required、incompatible 等会报告错误，optional 缺失报告 warning，recommended 缺失报告 info。该机制验证本机已存在的内容并给出排序约束，不负责下载、安装或解析版本解算方案。[Metadata codec](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/definition/meta/PackMetaData.java#L15-L44)、[依赖结构](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/definition/meta/dependency/PackDependency.java#L17-L54)、[校验语义](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/impl/depends/PackDependencyValidator.java#L29-L109)

排序器只将 `REQUIRED` 和 `OPTIONAL` 依赖的 `BEFORE`/`AFTER` 作为拓扑边；其他依赖类型不建立加载边。管理器把排序后的包列表展平为 KubeJS 的 ScriptPack 列表；循环或排序前提失败时报告错误并退回原 KubeJS packs。源码没有给无约束包承诺额外的稳定顺序。[边构造](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/impl/depends/PackDependencyBuilder.java#L13-L34)、[排序接线和失败分支](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/mixin/ScriptManagerMixin.java#L118-L141)

## Context、状态和脚本 API

`ScriptManagerMixin` 在每个 ScriptManager 上保存 `Map<namespace, Context>`。构建每个 ContentPack 时，`GraalScriptManager.loadContentPack` 为其 ID 创建 Graal Context 并附着到对应 ScriptPack；因此 Graal 分支可支持同一 ScriptType 中包间独立的 JS realm。未指定此结论适用于 Rhino 或所有 KubeJS 行为。[管理器 context map 与包循环](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/mixin/ScriptManagerMixin.java#L43-L59)、[为包建立 Context](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/graal/GraalScriptManager.java#L13-L47)

包脚本可通过 `__script__` 读取当前文件的 name、location、type、namespace、path 和 engine；这不是包私有状态对象。`ContentPacks.isLoaded/getMetadata/getAllMetadata` 读取当前 manager 的全包列表。`putShared(id, value)` 写入静态 `TYPED_GLOBALS[ScriptType][id]`；当前类型可读，也可显式读其他类型。键不含 ContentPack ID，源码中未见该静态表按包卸载或重载清理的路径。[每文件元数据和 Context eval](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/graal/GraalApi.java#L147-L219)、[`ContentPacks` 查询与共享状态](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/plugin/ContentPacksBinding.java#L40-L112)

KubeLoaderPlugin 增加 `ContentPacks`、`Registries`、`Perf`、`KLUtils`、`ModGen`、`PackGen`、`KLM`；BindingsEvent mixin 收集 manager 的 bindings，除 `Java` 特殊处理外交给 Graal Context。Graal 绑定将 EventGroup 包装为代理、Java class 转成 `Java.type`，其他对象直接放入 bindings。由此看出“Context 独立”不等于“可见 API 按包裁剪”。[公开 bindings](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/KubeLoaderPlugin.java#L36-L48)、[绑定收集](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/mixin/BindingsEventMixin.java#L18-L52)、[Graal 绑定转换](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/graal/GraalApi.java#L60-L100)

默认引擎可配置为 GraalJS 或 Rhino；脚本预读的 `//engine:` 支持 `graaljs`、`rhino`、`default_engine`、`both`。`both` 分别尝试 GraalJS 与 Rhino，因此一个文件可能运行两次。此处是文件级选择，不是 pack manifest 的引擎字段。[引擎枚举](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/definition/meta/Engine.java#L9-L17)、[文件头元数据](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/mixin/ScriptFileInfoMixin.java#L42-L45)、[按文件分派](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/scripts/KLScriptLoader.java#L90-L179)

**安全边界：** `GraalApi.createBaseContext` 使用 `HostAccess.ALL` 构建 HostAccess，设置 `allowAllAccess(true)`、全类名查找和 native access；这不是可复用的包沙箱配置。此处只记录选项，不据此断言特定漏洞或可利用路径。[Context 权限配置](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/graal/GraalApi.java#L222-L252)

## 文件夹、Mod JAR、资源和生成

默认文件夹 provider 扫描 `kubejs/contentpacks` 的直接子目录并解析 `contentpack.json`；包按 `<type>_scripts` 目录加载。`PathContentPackResources` 将目录中的 `assets/{namespace}` 与 `data/{namespace}` 作为 Minecraft PackResources 暴露。资源挂载由 Forge `AddPackFindersEvent` 单独接入，不是脚本执行 API 的副作用。[目录扫描](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/impl/path/PathContentPackProvider.java#L18-L46)、[脚本与资源路径](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/impl/path/PathContentPack.java#L31-L94)、[资源挂载接线](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/Kubeloader.java#L121-L141)

Mod provider 从已加载 mod 的 jar 查找 `contentpacks/contentpack.json`，脚本适配器再读取 `contentpacks/{type}_scripts` 与 `contentpacks/common_scripts`。`/kl mod` 生成器可把本机文件夹包的脚本目录复制进 `contentpacks/`，把 assets/data 复制到 jar 根目录，并生成 `mods.toml`、`pack.mcmeta` 与 JAR。它是导出为 Forge mod 的生成流程，不是运行时在线安装器。[mod jar 扫描](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/impl/mod/ModContentPackProvider.java#L18-L57)、[jar 中脚本读取](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/impl/mod/ModContentPack.java#L32-L70)、[生成与复制](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/utils/modgen/PackModGenerator.java#L26-L50)、[资源/脚本复制范围](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/utils/modgen/PackModGenerator.java#L146-L195)

普通目录包生成器创建 startup/server/client/common/mixin、assets、data、probe 目录并序列化 metadata。Zip adapter 已标记 deprecated，zip provider 在默认注册处被注释掉；虽然资源 repository source 仍挂载，但默认情况下没有该 provider 提供 ZipContentPack。[目录脚手架](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/utils/modgen/ContentPackGenerator.java#L26-L71)、[默认 Provider 注册](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/Kubeloader.java#L94-L114)、[Zip 状态](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/impl/zip/ZipContentPackProvider.java#L17-L39)

## 重载、失败与资源所有权

- 已确认的替换路径会先 `close()` 同 namespace 的旧 Graal Context，再尝试创建新 Context；创建失败不会保留可用旧 Context。调用点是 `ScriptManagerMixin` 的 ContentPack 循环。该实现不体现候选 Context 准备成功后再提交的失败原子替换。[实际加载调用点](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/mixin/ScriptManagerMixin.java#L84-L113)、[关闭旧 Context 后重建](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/graal/GraalScriptManager.java#L28-L47)
- 扫描/metadata 解析失败在 provider 边界被记录并跳过；Graal `eval` 的 `PolyglotException` 被记录后返回。排序失败只退回原始 KubeJS packs；这些分支没有展示对已发生脚本副作用的共同回滚协议。[eval 错误处理](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/graal/GraalApi.java#L102-L145)、[provider 单包错误](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/impl/path/PathContentPackProvider.java#L25-L45)
- in-scope 的 Context map 是普通 `HashMap`，检索到的 Context `close()` 仅在同名 Context 替换时出现；没有看到被移除 namespace 的遍历关闭路径或对 `ContentPacks.TYPED_GLOBALS` 的清理路径。这是源码范围内的生命周期观察，不证明 KubeJS 或其他平台没有额外清理。
- Context eval 直接调用 `context.eval`，Graal event handler 直接执行 guest `Value`；加载期使用 ThreadLocal 标记 Context，但这些代码没有显示跨线程调度/序列化或显式 owner-thread 检查。不能据此推断所有回调都会跨线程，也不能宣称它线程安全。[直接执行路径](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/graal/GraalApi.java#L147-L219)、[event 回调](https://github.com/WhiseNT/kubeloader/blob/1f5222c049ccdb0fd256e1bace9385176a59c6ba/src/main/java/com/whisent/kubeloader/graal/GraalApi.java#L303-L341)

## 对 NekoJS 的可借鉴范围

这份参照说明需要分别设计“包身份/元数据”“运行 Context”“模块与状态共享”“外部 API 权限”“资源挂载”“打包分发”。Kubeloader 用多个 Provider、平台资源 adapter、KubeJS mixin、Rhino/Graal 双路径和 JAR 生成器承载这些分工；这些组件数量本身不是复杂度或效果的证明。

较小的产品层借鉴是让作者能清楚表达包身份、依赖来源/版本范围和 before/after 约束，并提供可重复的目录/JAR 导出体验。若 NekoJS 决定增加 pack 私有 Context 或 pack 私有状态，那属于运行时所有权、API 可见性、错误回滚和资源清理的契约变化，不能由增加一个 `ContentPack` 接口完成。NekoJS 当前既有 `ScriptPack` manifest、ScriptType 和 runtime root 应先作基线；本报告不建议复制 Kubeloader 的实现或引入第二套 Provider/全局数据所有者。

## 未验证事项

- 未运行 Gradle、游戏、脚本或性能验证；本文是静态源码核对。
- Graal/Rhino 与其宿主库的行为以本仓库调用代码为界；未据此判定 KubeJS 未公开的内部线程保证、事件清理完整性或 Minecraft 资源重载时序。
- 资源处理以源码显式接线为准：默认启用文件夹包和 Mod JAR 扫描；Zip provider 默认未注册。没有据此推断其它外部插件是否会自行注册 Provider。
