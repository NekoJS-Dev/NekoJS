# NekuJS implementation plan

## Scope and constraints

Develop the independent `addons/nekujs` project for Minecraft 1.21.1 / NeoForge / Java 21 using the read-only reference checkout and six user-supplied fixture JARs. Preserve unrelated worktree changes, core ownership and the Stonecutter active node. NekoJS must not depend on this addon. Do not redistribute fixture binaries.

The user authorized a single JAR with NekuJS, KubeJS and Rhino provider identities, together with actual necessary Java APIs. Prefer a bounded native facade backed by NekoJS/Graal over a second evaluator. Document a concrete semantic blocker before proposing real Rhino. An identity satisfying a dependency range is not proof of complete compatibility.

## Implemented layers

1. Independent build/dev runs, managed fixture staging, packaging contracts and MC-independent binary audit.
2. Production discovery of original `kubejs.plugins.txt` entries from real loader roots, with dependency/side gates and duplicate validation before class loading/construction.
3. One production JAR declares `nekujs` 0.1.0, `kubejs` 2101.7.2-build.303 and `rhino` 2101.2.7-build.81. Native provider entry points and bounded Java ABI ship; original providers cannot coexist.
4. Original plugin hooks use native NekoJS event groups, bindings, type adapters and lifecycle. No additional guest Context/evaluator owner. Unsupported targeted subscription, immediate exits and unconnected registry/data operations reject explicitly.
5. Real component codecs and builder definitions are retained as metadata. Legacy schema execution/inheritance/functions and registry-object insertion remain unsupported, not silently accepted.
6. Optional strict resource-only Mekanism crushing profile import preserves raw JSON/counts. Actual serializer acceptance remains a separate gate.

## Ownership and review

- Lead owns integration, build/metadata, tests, final diff, Gradle processes and documentation.
- Discovery/utilities, native events and recipe/registry ABI were delegated in disjoint source scopes. Teammates did not run concurrent builds.
- Read-only investigators checked exact unchanged fixture descriptors, plugin static initialization, mixins and original event posting. Do not install a duplicate respawn hook: Additions already posts through its own NeoForge subscriber.
- Independent review found cross-phase wrapper selection and dedicated-server CLIENT-hook collection issues; phase-aware native wrapper registration now rejects absent-phase matches before conversion.
- Supported legacy events publish concrete native payload metadata for runtime validation and Probe. Unsupported targeted optional wrappers remain lazy; no broad catch substitutes a base event type.
- Native recipe overload selection treats conversion incompatibility separately from invocation failure. Execution failure must retain its cause and cannot become schema/raw fallback success. A measured Graal boundary erases custom ClassCastException identity/cause; native adapter registration preserves that execution failure before normalization, rather than substituting shape prechecks that would reject custom scalar conversions. Native null-to-primitive mappings also run through the boxed native target before an unconverted null is rejected; measured regressions cover successful and failing custom null adapters and all eight primitive defaults.
- The [recipe translation investigation](<research/2026-11-09-nekujs-recipe-translation.md>) records exact graph semantics, missing native capabilities and explicit profile exclusions. It is a design boundary, not a claim of implemented recipe compatibility.
