# 错误仪表盘 JSX 独立试作

## 目的与入口

将已选定的 [blue-a-2 HTML 原型](error-dashboard.prototype.html) 用现有 NekoJS JSX 原语实现，供真实游戏内观察布局与交互。用户明确选择先独立试作，再决定是否接真实错误；本轮不替换正式错误仪表盘，也不接入 ErrorTracker／网络 DTO。

源码：[error-dashboard-jsx.prototype.tsx](error-dashboard-jsx.prototype.tsx)。仅 NeoForge 26.1.2／26.2.0 CLIENT 支持。需使用包含原生 design 控件缩放修复的 NekoJS；旧 JAR 只缩放布局而不会同步缩放按钮和输入文字。更新 JAR 需重启游戏，之后修改试作脚本只需 reload CLIENT。

1. 只安装这一份自动打开的 UI 脚本到 `nekojs/client_scripts/prototypes/error-dashboard.prototype.tsx`。暂时将其他自动开 Screen 的试用脚本移出 `client_scripts`，先备份。
2. 进入测试世界，执行 `/nekojs reload client`。脚本在已有玩家时打开；启动早期只注册登录事件，不创建 Screen。
3. 试作面板外的控制栏可以切换正常／长文本／长原文／缺少源码／空列表场景，也可收起／重开面板；当前场景以蓝色按钮和控制栏文字标识。长原文包含 Error 消息 000–079 和原始详情 000–159，可分别测试框内滚动。全部状态只在本代脚本内存中。
4. Esc 先关闭模态，再关闭 Screen。Screen 关闭后，通过重新加载 CLIENT 再次打开；重新加载会重置本代演示状态。

## 已实现

- 冷深蓝／石板蓝、蓝色强调、错误红色，左右分栏与侧栏收起；按游戏内反馈铺满视口，仅在底部预留试作控制栏。不添加窗口最小化／最大化／关闭按钮。
- 保持原型左右分栏，左栏占 26%；使用 1280×720 设计画布，字号、按钮尺寸、卡片与间距按 `min(width/1280, height/720)` 同步缩放。原生 resize 保留设计尺寸，不切换为列表／详情两页，也不改 Minecraft 的 GUI 缩放设置。
- 使用 `id/path/line/count/message/fullDetails` 六字段。原 HTML 四组演示数据保持一致，额外增加“长原文”场景供独立滚动验收；不读取真实脚本或错误来源。
- 搜索路径、消息、ID、原始详情；匹配计数、累计次数、等高可点击卡片、独立列表和详情滚动。
- 原始详情与调用栈分别展开／收起，复制路径与完整原文；折叠不影响复制全文。
- 展开的原始详情与调用栈分别有独立滚动区域，内容高度上限为 160 个设计单位，并随整页比例缩放；标题条留在区域外。短内容按自然高度显示，超过上限才在框内滚动。右侧详情仍保留外层滚动，各自保存滚动位置。
- Error 消息框也有独立滚动，上限 96 个设计单位；左侧红色强调线保持固定。小数缩放下的多行文字由 Java 使用基础字体行距绘制，与总排版高度保持一致，末行不因逐行取整而不可达。
- Java 宿主自动复用有界排版结果、避免重复测量相同短前缀，并只提交可见行绘制。此优化不要求脚本分页或维护性能缓存，复制仍使用完整原文。测量与限制见 [原生长文本性能记录](../../implementation/2026-11-05-jsx-native-text-performance.md)。
- 折叠标题条使用原型的深灰背景、左对齐文字和蓝色方向三角，标题与内容共用外框，整条可点击；保留原生按钮的键盘操作与焦点高亮。普通操作按钮统一使用中性灰色。
- 详情标题与紧凑操作按钮保持同排，按钮靠右并使用原型的中性灰色；缩放不改变排列。消息区使用暗红背景与左侧红色强调线，不添加四边描边。
- VS Code 定位只展示演示计划，不检测文件、不启动外部程序。未知／虚拟位置禁用该动作。
- 剪贴板写入后读回确认；失败时显示重试对话框，不报告虚假复制成功。
- 复用 `Component.translatable`；新增演示文案通过 `ClientEvents.lang` 提供 en_us／zh_cn，并使用现有 `translatableWithFallback` 机制保证新翻译尚未载入时有英文文案。生成语言资源属于既有语言生成流程，不是错误数据持久化。切换语言／刷新资源后可再 reload CLIENT 更新界面。

## 与 HTML 的差异

- 使用原生单行 input、label、scroll、panel 和 button；没有 DOM／CSS、网页字体、圆角、阴影或浏览器文本选择语义。
- 搜索使用鼠标或 Tab 导航，未增加 `/` 全局聚焦能力。当前 JSX 没有公开的指定控件聚焦接口，试作不为此扩展引擎。
- 面板外“收起／重开”保留内存状态；Esc 关闭整个原生 Screen 后重新加载会重置，不能将 HTML 外部控制条直接移植成游戏外常驻控件。
- 采用原有 `coordinateSpace="design"` 的比例缩放；每个参与原语显式声明，root 转发器保留设计尺寸。缩放只重排同一棵 UI，不增加页面切换或逐帧轮询。此前尝试的紧凑导航已按用户要求撤回。
- 卡片通过自身范围内的透明按钮覆盖层接收输入，文字本身不拦截点击；没有全屏隐藏输入层。长文本在原生裁剪／滚动内显示，双行卡片预览采用固定高度裁剪。
- 这是可丢弃的独立试作，未加入发布资料 bundle，未修改正式错误 UI 路由或接入真实错误。为使原有 design 布局在原生控件上完整生效，补齐了按钮／输入框／滑块的缩放绘制与命中；普通 logical 控件行为保持不变。

## 当前验证

三项真实 TSX 编译／模块加载检查通过，覆盖交互、登录延迟，以及 960×540、426×250、320×240、1280×720 下始终保留双栏、26% 列表宽度、按钮边界、设计比例与搜索保留。两个 NeoForge 支持节点的原生聚焦回归各 42 项通过，包含 1/3、1/2、1、2 倍下的控制文字、点击、输入光标、拖选、横向滚动与滑块；最终 `:common:check` 通过：2736 项，零失败／错误，4 跳过；两个支持节点构建各 821 项，零失败／错误，85 跳过，各 3 项 platform gate 通过，guardLint 零警告。用户确认了全屏、图标与折叠栏样式，明确否决紧凑导航；新 JAR 已安装、游戏已重启并最大化，保留用户当前 GUI 缩放 3；Java 性能优化及长原文滚动的实机效果等待用户确认。CPU fixture 不能代替 GPU、剪贴板和物理输入验收。

用户随后反馈原文与 Error 仍不能滚动。新增小数边界回归复现 Java 绘制行距累积取整导致末行不可达；修复后，四种视口均验证三个区域的末行绘制。最新完整构建为 common 2736 项、两支持节点各 827 项，零失败／错误；新增 Error 独立滚动与编号长文本等待用户手测。详见 [最新小数缩放修订记录](../../implementation/2026-11-05-jsx-fractional-text-scroll.md)。

用户已确认 Error／原文滚动没有问题，后续要求增加位置提示。Java 宿主现为溢出的 scroll 自动绘制可拖动、可点击轨道翻页的滚动条；试作脚本未改。最终构建为 common 2736 项、两节点各 835 项，零失败／错误；新 JAR 已安装、游戏已重启为大窗口，滚动条观感和物理输入待用户确认。详见 [原生默认滚动条记录](../../implementation/2026-11-05-jsx-native-scrollbars.md)。

首轮实机截图确认初版界面已打开，但居中且仅占上半屏；用户要求全屏。修订去掉外层留白和最大宽度，并在隐藏主面板／占位块时将其高度设为零，避免当前布局器将隐藏的 fill 子项计入剩余高度分配。若布局器以后排除隐藏项，可移除这处显式零高度。数组回调先绑定具名接收者，避免当前预检对字面量接收者的误报；没有关闭或放宽校验。

原型最初遇到两种现有编译器限制：嵌套 JSX map 内的自闭合组件，以及对象字面量中包含引号／右花括号的原始报错文字。分别改用 `UI.element` 和等价 JSON 数据输入，未修改编译器或原始六字段内容。调试输出未保留在测试源码中。
