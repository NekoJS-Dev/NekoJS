# 被取代的正式样本（第一遍，2026-09-12）

这 4 个运行是**第一遍正式采样**，数据本身有效，但已被 `../formal/` 的第二遍取代。取代原因不是数值错误，
而是 **harness 在 code-review 后修改了**，归档样本必须由与仓库提交版本一致的 harness 产出：

| 差异 | 第一遍 | 第二遍（当前 formal） |
|---|---|---|
| stdin 试验 | 每个 Mode 首个会话都试一次 stdin（白等 60 s，并把首轮 tick 采样窗口拉长 ~60 s） | 默认只走 RCON；试验改为显式 `-TestStdin` |
| tick 行数统计 | 停服**前**统计 → jsonl 的 `tick_rows` 与归档 CSV 行数不一致（1201 vs 2405） | 停服后统计，两者一致 |
| 会话 gen | 各 fixture 各自 `Date.now()`/`globalThis` 传递 → eval 的 gen 比 tick/adapter/mem 早 |
| 第二轮起共享 harness 写的会话 gen（`perf-out/GEN`） |
| `Send-TimedCommand` 超时参数 | 未生效（死参数） | 透传到 `rcon.py` |

**两遍数值对照（同一 revision `3400e97e`、同一节点与数据集）**：

| 维度 | 第一遍 | 第二遍 |
|---|---|---|
| startup formal wall_done_ms | 13220 / 24011 / 24391 / 16523 / 14338（p50 16523） | 30172 / 16034 / 14926 / 24379 / 24385（p50 24379） |
| reload rcon_rtt_ms | 239 / 125 / 96 / 104 / 117（p50 117） | 228 / 122 / 123 / 113 / 110（p50 122） |
| tick p50 | 49.98 / 50.01 / 50.02 ms | 47.30 / 49.95 / 47.08 ms |
| adapter 稳态 p50 | 8.80 / 6.87 / 7.43 µs/op | 10.20 / 7.81 / 7.57 µs/op |
| eval 稳态 p50 | 95.2 / 101.5 / 57.8 ns/op | 127.2 / 54.1 / 193.9 ns/op |
| probe self（正式 5 个） | 440 / 361 / 330 / 780 / 390 ms | 779 / 747 / 622 / 586 / 651 ms |

结论：**跨会话离散度远大于 harness 版本差异**——startup、adapter、eval、probe 的四轮 p50 在两遍之间移动
幅度与同一遍内轮间移动幅度同量级（eval 尤其明显：第二遍轮 3 的 p50 193.9 ns/op 是第一遍轮 3 的 3.35 倍）。
因此本基线只报**范围与 p50**，任何单点数字都不得跨会话比较；P4 复测必须在同一会话内做对照，
或接受同量级的会话间噪声（见基線报告 §3、§8 A7）。
