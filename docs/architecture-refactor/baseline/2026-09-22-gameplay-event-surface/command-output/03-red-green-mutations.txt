## 突变 A+B：清理层逐层摘除（defense-in-depth characterization，如实记录为「绿」）

注入点 A（EventBusJS.finishPending：旧 generation 的 bus.unregister 循环被删除）

解释（characterization，非测试缺陷）：「reload 后无重复 dispatch」由三层独立机制共同保证——
1) commit 点旧 token 的 bus.unregister（突变 A 摘除）；
2) 旧 generation 闭包的 dead-context 跳过（突变 B 摘除）；
3) 旧 generation Graal Context 已 close，残余监听器执行即抛、被分发包装的 try/catch
   记为回调错误，不再产生可见派发（无法用单点突变摘除，除非直接改 Graal 语义）。
单层/双层摘除被剩余层掩盖；只有真正的双重激活（突变 C）才让重复派发可观察。
结论：无重复 dispatch 是多机制冗余保证，突变 C/D 证明 fixture 对可观察缺陷形态敏感。
