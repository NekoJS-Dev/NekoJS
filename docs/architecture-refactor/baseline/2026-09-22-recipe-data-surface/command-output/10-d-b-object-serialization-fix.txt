=== Ticket 23 defect D-B fix: json(path, {jsObject}) serialized as [object Object] ===
Worktree ../NekoJS-mult-t23fx (branch ticket-23-serialization), 2026-09-29, maintainer ruling FIX IT.

Root cause (real-engine probe): values proxied from GraalJS into an Object-typed host parameter
arrive as host Map/List proxies (PolyglotMap/PolyglotList), never as graal.graalvm.polyglot.Value,
so the old `value instanceof Value` branch was unreachable from in-context script calls and the
String.valueOf fallback wrote the proxy's JS toString() verbatim: "[object Object]".

--- Fix summary ---
- JsonObjectAdapter.convertHostValueToJson(Object): shared conversion for values received on
  Object-typed parameters — null -> JsonNull, Value/JsonElement pass through, String/Boolean/
  Number -> primitive, Map -> JsonObject, List -> JsonArray, anything else is rejected with an
  English IllegalArgumentException instead of being silently stringified.
- DataGeneratorJS.json: null/undefined (Java null) explicitly rejected in English ("value must
  not be null or undefined (path: ...)"); String arguments keep the JSON-string verbatim
  passthrough form; all other shapes go through convertHostValueToJson.
- Sibling check: LangGeneratorJS (add/addAll(Map)) does not use this boundary and Map-typed
  parameters already work (AdvancedJavaInteropSmokeTest); plugin generateAssets and script
  ClientEvents.generateAssets share DataGeneratorJS.json and are covered by the same fix;
  AssetGeneratorJS uses Value-typed parameters (ticket 29 domain, untouched). Related but out
  of D-B scope, recorded not fixed: the loot wrapper family LootTableJS.toJsonElement(Object)
  is likewise blind to Map proxies, but fails with an explicit exception instead of writing
  garbage.
