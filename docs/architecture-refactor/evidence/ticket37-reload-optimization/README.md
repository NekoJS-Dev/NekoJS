## Change and ownership

`NekoModulePipelineCache.prepareBuiltinSource` retains immutable Graal `Source` objects for bundled `nekojs/node/` manifest entries in the existing runtime owner's cache. Generation sessions share that metadata through the already-paired root/session ownership; there is no process-wide singleton, new runtime owner, Point or Plugin Hook.

`NekoNodeModuleInstaller` prepares each bundled resource once per owner: resource read, fixed built-in TypeScript erasure and Source construction. **Each Context still evaluates every manifest entry in original order.** Guest exports, listeners, timers, module instances and mutable state remain generation-owned. Plugin module wrapping/evaluation and user module mtime/size/hash/language/compiler/schema/security validation are not cached through this new route and remain unchanged. The manifest itself is read each install, so no independent manifest catalog is invented.

Session close or type-specific invalidation leaves root-owned builtin metadata intact. Owner-wide clear/close removes it; failed preparation is not retained and retries remain possible. The cache lifetime is the shipped classloader/resource snapshot plus its runtime owner, not mutable pack/user-source lifetime. Changing bundled code requires the normal updated-runtime/new-owner or explicit owner-wide clear boundary; this change does not promise hot replacement of mod classpath files within an existing owner. Only immutable Source metadata is shared, never a Context or guest Value. Script-facing APIs, saved data, wire contracts, ClassFilter and host-access rules are unchanged.
