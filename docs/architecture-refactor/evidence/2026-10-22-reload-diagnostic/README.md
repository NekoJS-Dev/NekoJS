# 当前候选重载阶段诊断

正式验收仍为[重载失败、启动通过](../2026-10-22-candidate-performance/README.md)。本归档的两轮录制是诊断，不能替代正式样本或改变门槛。

第一轮不改源码，以内置 JFR profile 和 2ms 执行采样记录 10 次真实 RCON 重载，交替发送 10 次 `list` 查询。32 个服务端 root 样本只显示耗时分散，不能据此确认单一根因。

第二轮在专用检出中临时添加阶段事件，分别记录墙钟与当前线程 CPU 时间；10 次重载的均值如下。CPU 时间分辨率有限，小阶段的 CPU 均值可能略高于墙钟。

| 阶段 | 墙钟均值 ms | CPU 均值 ms |
|---|---:|---:|
| 候选环境准备 | 21.09 | 21.88 |
| 绑定安装 | 10.25 | 7.81 |
| 脚本发现与执行 | 62.94 | 54.69 |
| 提交与旧代释放 | 3.59 | 3.12 |
| root 重载合计 | 100.63 | 87.50 |
| 配方重新应用 | 47.63 | 45.31 |
| 命令合计 | 149.34 | 132.81 |

这批诊断表明脚本执行准备和配方解码都值得继续分解，不证明本批耗时等于正式采样时的耗时。配方钩子、当前 schema 校验、权限和旧代释放不能直接跳过。

两轮服务端均正常 RCON 退出。最初临时插入位置落到 Stonecutter 尾部 guard 之后，构建失败且未启动游戏；原文件恢复后用新目录修正位置再运行，失败材料保留。最终两处临时源码均恢复，重新构建后全部 1638 个生产类和 JAR 与正式候选逐字节一致。

归档包含阶段明细、窗口、执行/分析工具、临时补丁、构建与进程日志和恢复证明；原始 JFR 可能含环境/系统属性，因此只保留本地，导出哈希及派生分析。导出文本检查 RCON 凭据并在必要时脱敏；不包含 server.properties、世界或启动参数。
