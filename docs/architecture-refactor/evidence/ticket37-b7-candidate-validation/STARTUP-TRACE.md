## Actual STARTUP contract

There is no script `event.create`. [`RegistryEventJS.create`](../../../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryEventJS.java#L52) is the static Java adapter factory. The Proxy member map consists of sugar methods, `custom` and `register` (lines73-75), while `getMemberKeys` advertises sugars with a usable default factory plus the two advanced operations (lines97-106).

- Sugar accepts exactly `(id, callback)` or `(id, typeName, callback)` and returns a `BuilderSurface` for the selected builder, not boolean; callback is mandatory and executable. See [runtime145](../../../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryEventJS.java#L145) and [shared callback209](../../../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryEventJS.java#L209).
- `custom(id, typeName, callback)` accepts exactly3arguments, resolves a globally unique type name, rejects ambiguous names and returns the selected builder surface. All current built-ins use `basic`, so that built-in name is ambiguous across registries; do not invent a valid `custom(..., 'basic', ...)` example. See [custom160](../../../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryEventJS.java#L160).
- `register(registry, id, supplier)` accepts exactly3arguments. Registry is a sugar or full `ns:path`, supplier is executable, and return is an anonymous generic builder surface, NOT the supplier's created object or `T`. Object creation occurs later in the registration pass. See [register184](../../../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryEventJS.java#L184). `build`, `get` and additional-object operations are excluded from the builder script contract ([contract43](../../../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryBuilderContract.java#L43)).
- IDs accept strings and host Identifier objects ([parseId257](../../../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryEventJS.java#L257)); a strings-only declaration is a supported narrow view, not the complete accepted input union.

## Metadata capabilities and limits

[EventPayload59](../../../../common/src/main/java/com/tkisor/nekojs/api/catalog/RegistryBuilderSurfaceEntry.java#L59) holds exact host identity, a payload name and Member strings. It CAN express required callbacks,2/3argument overloads, concrete builder returns, raw union/literal spellings and conservative Supplier/custom Any fallbacks. Identity resolution is explicit ([resolver19](../../../../common/src/main/java/com/tkisor/nekojs/probe/EventPayloadDeclarations.java#L19)), not a builder-name/typeName inference.

It does NOT declare standalone helper types, type parameters/bindings, imported host dependencies, per-payload builder module dependencies or a backend-independent union/generic AST. Raw strings can spell a union or TypeVar but do not resolve/import its symbols. Python imports Any/Callable/overload/Protocol plus associated builder names, not Literal/TypeVar or arbitrary host symbols. [Python event member86](../../../../common/src/main/java/com/tkisor/nekojs/probe/backend/python/PythonEventRenderer.java#L86) does not add overload decorators for repeated method names, unlike [builder renderer37](../../../../common/src/main/java/com/tkisor/nekojs/probe/backend/python/RegistryBuilderPyRenderer.java#L37). Factories registered without a builder class are valid ([types55](../../../../src/main/java/com/tkisor/nekojs/wrapper/registry/gen/RegistryTypesPoint.java#L55)) but have no structured builder entry. Do not silently drop their runtime sugar/advanced route or invent a precise builder from the class-backed subset.
