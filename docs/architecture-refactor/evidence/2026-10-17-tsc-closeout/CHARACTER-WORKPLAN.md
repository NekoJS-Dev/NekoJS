已复现的共同原因候选：普通字符参数生成 `string`，但 `Character` 返回值、泛型实参和数组元素仍生成 `$Character`。例如 Guava `CharMatcher` 与 `Predicate<Character>`、fastutil 的 char 函数继承链不一致。

2. 三个排序假设：TS 值类型投影缺失；仅输入别名丢失；继承泛型替换错误。通过分别检查 IR、输入/返回投影与真实 Graal 调用区分。
3. 优先在 TS 共享渲染处修复，不改变共享 IR 和 Python 语义；保留显式槽编辑、真实 Java 成员、继承与现有适配器优先级。不使用空声明、批量 any 或 skipLibCheck。
4. 执行 common check、Probe 严格类型、五节点构建和实际制品完整默认 TSC/Pyright 对照；记录逐条新增/移除和失败，更新必要的 canonical goldens。
5. 验证后 commit，不创建 PR。完整 IDE、正式性能、客户端和最终候选回滚继续分别验收。
