# 当前重载节奏的阶段诊断

候选源码 `7bea6d6d`。正式验收仍为[重载 340.0 / 292.8 ms 失败、启动通过](../2026-10-22-source-facts-performance/README.md)；本归档只用于定位，不能替代正式样本。

服务器启动时启用 JFR，进入 Done 后每隔 3 秒执行一次真实 RCON 重载，共 5 次，不交替插入其他查询。采样函数沿用原工具；诊断启动增加 JFR 参数与临时阶段事件，故不称为无干扰正式计时。分析仅保留五个命令窗口内的阶段，排除启动期间同名事件。

每次重载执行六个入口；预检和模块求值按 30 个入口事件汇总后除以 5。完整阶段表也保留每入口均值，不能将该均值当作整次重载。root 的执行采样仅 15 个、配方阶段 17 个，不能据此确认某个叶函数是唯一根因。条件过滤耗时较小，本批没有据此加入跳过路径或复用可变 Recipe 对象。

另用实际六个 fixture 的正文做 24 轮纯编译比较，前 4 轮热身、之后 20 轮交替先后顺序。`new Function` 均值 10.57 ms / 中位 3.92 ms，共享纯 Source 均值 1.43 ms / 中位 0.81 ms。这是独立引擎下的编译诊断，未执行模块，也未覆盖真实加载、权限、模块循环或错误定位；不能外推为重载性能收益。未采用该实验改变 CommonJS 语义或增加生产缓存。首轮遗漏生产的 ecmascript-version 选项，受 Nashorn 默认语法限制而失败，日志保留；不归因于生产引擎。

首个诊断尝试的 Gradle init 脚本缺少 included-build 节点判空，未启动游戏；第二个尝试因 Mixin 嵌套事件类重映射失败，游戏进程退出 1，未到 Done。两次失败材料保留。第三次改用普通诊断类，五次重载全部 COMMIT，服务器经 RCON 正常退出、无强杀。

诊断后五处临时源码全部恢复，重新构建后 1640 个生产类和 JAR 与正式候选逐字节一致。原始 JFR 仅留本地（可能含 JVM 属性），归档包含哈希、阶段与堆栈派生分析、控制脚本、临时补丁、源码绑定、恢复证明及失败尝试。导出检查并脱敏 RCON 凭据，不包含世界或 server.properties。
